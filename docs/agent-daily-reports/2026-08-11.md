## 一、这批最值钱的一件事:停服实测证明了「断言绿 ≠ 做完了」

D17 上一轮自请标 🔧,欠的就是这一步。补上之后,**断言层全绿的三页里塌了两页**:

| 页面 | 断言层 | 停服实测(店主会看到的那一层) |
|---|---|---|
| services | ✅ | ✅ 失败态居中,与书面标准一致 |
| home | ✅ | ❌ 失败态**叠在残缺骨架上** |
| booking | ✅ | ❌ **纯白屏**,连「加载失败」都没有 |

- **booking 白屏**根因:失败态块被写在 `wx:if="{{service}}"` 闸门**里面**,而
  `getService()` 本身就会抛 —— service 取不到 → 闸门为假 → 失败态跟着一起不渲染。
  上一轮我自己说过「把假数据换成白屏所以不推」,结果推上去的正是一处白屏。
- **home 残缺骨架**根因:只加 `wx:if` 没排除正文。一边说"加载失败",下面继续摆
  半张门店卡(缓存店名 +空地址/空营业时间/空电话),再往下还悬着两个「人气美甲/
  人气美睫」空标题 —— 正是《闭环回归纪律》禁止的"单独蹦出来找不到上下文"。

**教训**:这两处都不是写漏了逻辑,是**只在能断言的那一层验过**。
L1 末端验证律不是流程装饰,它是这两个缺陷唯一的出口。

## 三、D9 结案:工具的锅和真缺陷,各一半

两轮没定论,这次用**三路对照实验**当场分开了。同一个手机号框、同一时刻:

| 路径 | data | 框里显示 |
|---|---|---|
| 触发 `onDsPhone`(等价人手敲键) | `"13800130000"` | `"13800130000"` ✅ |
| automator `.input()` | `"13900139000"` | **`"undefined"`** ❌ |
| 对照:`.input()` 写 `type=text` 的框 | 正确 | 正确 ✅ |

**结论**:字面 "undefined" 是 **miniprogram-automator 写 `type="number"` 输入框时
自己造出来的**,不是产品缺陷 —— 工具的锅,和 D15 一样。

**但产品这边有一处真缺陷,正是它让工具的痕迹变成店主看得见的鬼**:
那两个框**没有 value 绑定(非受控)**。后果两层:
① 显示值与 data 脱钩;② `tapFree()` 每次开面板都把 dsName/dsPhone 重置成 `''`,
但没有 value 绑定这个重置**清不掉框里的字** —— 这就是店主说的「改不动删不掉」。

已改受控。L5 5/5:开面板必空 → 显示恒等于 data → 关掉重开必清。

**排查纪律入档**(写进 `handoff/自动化占用中.txt`):用自动化验输入框之前先做这个三路
对照;`type="number"` 的框一律不用 `.input()` 验,改用 callMethod 触发真实 handler。
不立这条,下一个输入框缺陷还会再耗两轮。

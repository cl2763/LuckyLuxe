## 真机调试联通件(店主 08-23 报「真机登录失败」)
- **查明**:手机上的 `127.0.0.1` 指的是手机自己——本机服务又只绑 `127.0.0.1`(`listen(PORT, HOST || '127.0.0.1')`),两头都不通,所以真机怎么点都连不上,与账号密码无关。
- **①连通**:本机开发默认绑 `0.0.0.0`(生产仍按 HOST 环境变量,Railway 不受影响),启动日志直接打印「真机调试地址(手机与本机同一 Wi-Fi):http://<局域网IP>:PORT」;小程序 `utils/api.js` 按运行环境**自动切 base**——`platform === 'devtools'` 用回环、真机用 `utils/devhost.js` 的局域网 IP;`devhost.js` 由根目录「更新真机调试地址.command」一键写入(换网络重跑一次,不改代码,脚本自带 /health 自检与防火墙提示)。仿真验证:devtools→127.0.0.1:4310、ios/android→192.168.0.104:4310。
- **②白名单红线(四之十)**:演示白名单以前只靠「云端别设 ALLOW_DEMO_ADMIN_LOGIN」——那是配置纪律,配错一次就是任何人邮箱+任意密码进真库。现在改成 `DEMO_LOGIN_ALLOWED = !IS_PRODUCTION && env`:**生产进程里恒 false,误配也开不了**;演示登录/演示注册/演示种子/openid 演示回落五处全走这一个判据(裸读环境变量零残留,断言常驻)。生产绝不建测试账号,测试档案只在沙箱库。

## 一、⑤ 跨租户泄露 —— 红线,现修(03t「入册不现修」的例外正是它)

一家店的订单接口把另一家店顾客的姓名、电话、邮箱、openid 整个对象下发——这是多租户产品最不能破的那条线,不排队。三件按顺序:

1. **堵口**:建单取顾客改 `WHERE id = ? AND tenant_id = ?`,取不到 → 4xx `CUSTOMER_NOT_IN_TENANT`。**同族扫尽先出清单**:全仓凡按 id 取租户所有物(users / customers / technicians / services / bookings / settlements / stored-value…)而 SQL 里没有 `tenant_id` 的语句,逐处标「改 / 不改+理由」(平台后台跨店的读口是合法例外,写明)。读口也补第二道:`/admin/bookings` 拼顾客对象时按 `bookings.tenant_id = users.tenant_id` 连,连不上就只下发 `customer_id`,不下发对象——读写两道闸第五案。
2. **常驻刀**:①静态白名单式——租户所有物按 id 取值的语句必须带 `tenant_id`,例外逐条写理由;②行为层(沙箱)——A 店拿 B 店顾客 id 建单必 4xx;A 店订单列表响应体里不得出现任何非本店 `tenant_id` 的用户对象。**先造病验红**(把那五行当已知阳性,刀必须咬到)。
3. **两库那五行**:先查引用闭包(结算/账本/小记有没有挂在这五单上)。**沙箱**直接删。**本机库 4128**:此件即批文——备份→打数→删五行及闭包→打数差值=闭包;若闭包里有账本行,停,按冲销规则另报。**生产**:只读查一次「单的租户 ≠ 顾客的租户」的行数,回执只写数字;>0 停下报我,一个字不写。

## 二、③ 储值页「购买」死按钮 —— 拆,现在

`bindtap="soon"` 没有处理函数,点了什么都不发生:这是「摆着又不响」,不可用即不呈现。**按钮整个拿掉**,不换成「即将开放」——线上自助购卡是 S2 的活,做出来再摆按钮。「充值套餐 示例」那块与「我的消息」同一口径:样例只在演示店显示,真店只出真空态。诉求总账里「web-only 豁免」那条记录按你的现测改掉:两端都不能。

## 三、②①④ —— 记缺口,入功能批,不在结案批动

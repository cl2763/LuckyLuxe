## 一、第一轮验收 · 三处小病(都不拦收货,随 D131 一起交)

### 1. ⑤ 的盲区:被 `.gitignore` 挡住的脚本对 ⑤ 也是隐形的

⑤ 用 `git ls-files --others --exclude-standard`,所以谁往 `.gitignore` 里加一行 `tools/foo.mjs`,那个脚本对 ⑤ 和三条护栏刀就都不存在了。我现测 `git ls-files --others --ignored --exclude-standard | grep -E '^(tools|apps/api)/.*\.(mjs|sh)$'` 当前为 0——**趁 0 立刀**:加 ⑤b,这条命令必须为 0(node_modules 之类的目录例外要写理由)。

### 2. 拆档「第二遍按行修」的口径要再窄一档:证据确凿 = 同一个人,不是「恰好在这个租户」

现在的口径(`migrate-cross-tenant-bookings.mjs:131–135`):这一行自己串味 **且 这张单的顾客在这一行的租户里** → 把行指到单的顾客。你自己写的反例「带朋友来」正好能穿过它:A 在小婕店的单上,朋友 B 的结算单一行,B 的档案**也被 DEFAULT 吞进了旗舰店**(这正是本脚本要处理的那一群人)→ 这一行串味成立、单的顾客 A 在小婕店成立 → **B 的结算单被指给 A**。本机库现测 0 条不等于设计上不会有。

改法:再加一个条件——**旧档案与新档案是同一个人**(`wechat_open_id` / `phone` / `email` 任一相等且非空;新建路径本来就是复制这三个字段过去的,所以真正落单的行一定满足);不满足的行**只打印不动**,归入「要人看」。造病:自造「带朋友」那一形状(B 被吞、结算单挂 A 的单)→ 脚本必须**一行不动**并把它列在「要人看」里。

### 3. `.env.ai-sandbox` 目前**不存在**,措辞要准

回执写「文件已被 ignore(上表有 check-ignore 输出)」——`git check-ignore` 对不存在的路径也会答,现查 `apps/api/.env.ai-sandbox` 没有这个文件。这是对的(你不该建它),但回执要写成「规则已生效,文件由店主建」。店主怎么建见 §四。

## 二、🔴 D131 九处裁:全修、不白名单,`quote_requests`/`reminder_tasks` 两处升红线先修

### 为什么这两处是红线(我读码)

- `createQuoteRequest`(`local-server.mjs:4980–`)的 `INSERT INTO quote_requests` 不带 `tenant_id` → 落 DEFAULT `lucky-luxe`;
- 而 **AI 报价状态机读它时按租户找**:`quote-state.mjs:86` `SELECT * FROM quote_requests WHERE conversation_id = ? AND tenant_id = ?`、`:124` 同;报价台 `local-server.mjs:5108/5109` 也按 `tenant_id` 列出。
- 结果:**小婕店的顾客提一次报价,单落在旗舰店名下**——小婕店的状态机按 `jics-nail` 找**永远找不到自己刚建的单**(状态机在非默认租户下是断的),而旗舰店的报价台**列得出别店顾客的报价**(跨租户泄露)。`scheduleReminderTask`(`:4970–`)同病:提醒挂到旗舰店。
- 这两条正卡在 12 场景要测的那条路上。**不先修,非默认租户的场景会为一个已知原因红**;只在默认租户下跑,又正好测不出它。

### 九处怎么修(全部显式写 `tenant_id`,一处不白名单)

| 处 | 修法 |
|---|---|
| `quote_requests` 4984(真业务口)· `reminder_tasks` 4974(真业务口) | **红线现修**:`currentTenantId()`(或从传入的 customer/conversation 取,三者必须一致,不一致抛错——一个字段只回答一个问题) |
| `admin_accounts`(`admin-auth.mjs:14` 首个老板账号) | 显式 `DEFAULT_TENANT_ID`;这是平台首启的旗舰店老板,写明白 |
| `stores` 1203 · `technicians` 1207 · `services` 1222(旗舰店初始种子) | 显式 `DEFAULT_TENANT_ID`(它们本来就是旗舰店的种子,写明白就不再靠列默认) |
| `bookings` 14353 · `wechat_conversations` 14398 · `quote_requests` 14423(演示种子) | 显式演示租户 id(种子函数拿到的那个租户) |

**判据**:
1. 静态刀 `test-tenant-explicit` 的棘轮从 ≤9 落到 **0**,并从此改成硬规则(反向守 31 张表/≥60 处不变);
2. **行为判据(非默认租户)**:沙箱里挑一个非 `lucky-luxe` 的租户,从顾客端正门提一次报价 → `quote_requests.tenant_id` = 该租户,`quote-state` 的 `quoted` 查询**找得到它**;同一动作产生的 `reminder_tasks.tenant_id` = 该租户;旗舰店报价台**列不出**它;
3. **造病**:把 4984 的 `tenant_id` 再去掉 → 静态红 + 行为判据 2 红(非默认租户找不到、旗舰店列得出);
4. 存量:本机库/沙箱库现查 `quote_requests`/`reminder_tasks` 里「行的租户 ≠ 其 user 的租户」各多少行,**报数**;修与不修随 D130 存量那一套(条件更新、备份先、逐表对照);生产**只读报两数**。

## 三、12 场景执行口径补三条(在 04a §四 之上)

1. **先出「source 地图」再跑**:现扫出的 `reply.source` 值我数了 29 个(`quote_intake_template` / `quote_intake_state` / `quote_draft_guard` / `quote_waiting_state` / `tenant_kb` / `after_sales_route` …)。逐个标:**到不到模型层**(路径上是否经过 `aiJson`),写成一张表放在走查文档头部。没有这张表,「12 场景打了真模型」这句话没法证伪。
2. **每轮记 `reply.source` + `reply.provider`**(你已提的),再加一列**「预期 source」**:每个场景每一轮事先写好预期走规则层还是模型层,实测不符就是一条发现(规则层抢答了该模型答的,或反过来),不许事后解释。**一个场景若没有任何一轮到模型层,它不算真模型场景**,矩阵里得换。
3. **租户维度**:12 场景**至少 6 个在非默认租户下跑**(沙箱 45 家租户里挑小婕店镜像那家),其余在旗舰店;两组各自的 `quote state` 快照都要交。理由就是 §二:默认租户把「靠默认值凑对」的病全遮住了。

其余不变:只打 4310;`AI_REQUIRE_REAL=true`;红了先归因、改夹具不算修;抖动场景 3 次报 n/3;费用报总 token;走查文档过 `test-credential-scan`。顺序:**§二 两处红线修完 → 店主填五行 → 开跑**。

## 二、硬拦与红线(全部真调用)

| # | 规则 | 断言 |
|---|---|---|
| D1 | 退款额 > 余额 → 拒 | ②-1 超 1 分即 400 `REFUND_EXCEEDS_BALANCE` |
| D2 | 退次数 > 剩余 → 拒 | ⑧-3 400 `REFUND_EXCEEDS_TIMES` |
| D3 | 原因没填 → 拒 | ②-2 只有空格也拒;⑧-4 次卡同款 |
| D4 | **退卡记成负收入 → 永不发生** | ③-3/③-4:退款前后**收入表一分不变、财务账本一行没多**(直连库取值) |
| D5 | 不许复用 reversal | ④-1 落的是 `refund`;④-4 两类型能分开统计 |
| — | 账本只许追加 | ⑤-2 第二笔退款写完,第一笔那行**一个字节没改** |
| — | 退完的次数不能再核销 | ⑨ 用退干净的卡开单 = 400 `TIMECARD_USED_UP` |
| — | 退次数不写 `used_times` | ⑧-7 `used_times` 仍是 4、`refunded_times` = 6 |

## 四、假设清单(图上没画、按最合理做并记档)
1. 退款方式落 `cash / transfer / original / other`。
2. **退卡不写 finance_transactions**:充值本来就不进财务账本(充值=负债);
   退款若写一条支出,报表会出现"没有对应收入的支出",反而把利润做错。日结单独一行留痕。
3. 次卡退次记 `refunded_times` 新列,**不动 used_times**;剩余 = 总次 − 已核销 − 已退,**唯一出口** `timecardRemainingOf`。
4. 顾客端类型文案改后端 `typeText`(小程序本地词典退役)。
5. 退卡与充值同权(老板 + 员工)。
6. 退卡**不加 D25 绑定闸**:钱已经在卡上,退还给顾客不该被绑定状态挡住。
7. 过期次卡也可退(退不退是商家的决定),但按钮上标「已过期」。

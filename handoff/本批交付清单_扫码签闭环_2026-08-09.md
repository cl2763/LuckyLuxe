## 本批 corner case(六类制度 + 店主点名)

| 类别 | 用例 |
|---|---|
| 并发时序 | **推送+扫码双端同时打开、同时点签 → 只成一次**(先签为准,另一端变已签只读) |
| 异常输入 | **未绑定顾客扫到别人单的码** → 确认卡显示**该单单主**的名字;单→档案不受影响 |
| 边界/幂等 | **会员码扫到已绑定档案** → 不重复绑、不报错 |
| 空态 | **轻档案无手机号**走全链(建单→结算→扫码→绑定) |
| 越权/冲突 | **openid 已绑本店另一档案** → 不覆盖、签字照走、进人工合并队列 |
| 边界值 | **一次性签署码过期与重发** |
| 幂等 | 重复点「推送签署」不产生第二张单 / 重复绑定不产生第二条身份 |
| 越权 | 未登录取二维码 401;跨店取别家单的二维码 404;员工只能排自己列 |
| 财务红线 | 常驻:¥10,000 充值不进业绩;**定金守恒审计 ok=true** |

### 核验中查出并修掉的两处

1. **绑定判定错了,S2 徽标一直不出现** —— `isUserBound()` 把 `user_identities` 里任何一行都算成"已绑定",而**顾客导入会写一条 `provider='phone'` 的身份行**(只是留了手机号)。轻档案因此被误判成已绑定,徽标永远不显示。改成只认 `provider LIKE 'wechat%'`,并加断言锁住。**这条只有并排核验才查得出来 —— 接口自己是"正常"的。**
2. **「未收」被渲染成红色告警态** —— 沿用了旧的「未付定金」样式。现场即时单本来就通常不收,红色读起来像出错。改成普通选中态。

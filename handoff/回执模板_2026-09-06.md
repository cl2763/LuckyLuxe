# 回执模板(店主 2026-09-06 于 05l 定;两处新增已并入)

> 用法:每批交付照这个骨架写。**填不出来的那一项,就是没做的那一步。**
> 本模板只加不删 —— 既有纪律(六项结构、L1–L5 自评、两库对照刀打印行)一条没动。

## 头部(必须在最前面,跑回归**之前**就写)

```
> 本批含开机迁移:〈表 / 列〉—— 4128 起服即落。
>   (没有就写:本批不含开机迁移。)
> 生产库:〈动了没有〉。本机库:〈由 tools/receipt-db-proof.sh 打印的那一行,原样贴〉。
```

**为什么这一行要写在跑回归之前**(店主 05l 立):
④ 那批新建表 + 加列是**开机迁移**,回归收尾会把 4128 拉起来、迁移当场就落进本机库。
我是**事后**在对照表里才发现「本机库有动」的 —— 顺序反了。
**开机迁移是自己写的代码,写的时候就知道,不该等刀来告诉你。**

## 主体:回报固定六项

1. **改了什么**
2. **在哪一层验的** —— 断言层 / 接口层 / **店主看得见那一层**(L1 末端验证律)
3. **同类扫尽** —— 这个缺陷属于哪一类?全仓还有几处?给机械搜索证据(0 残留)
4. **用什么数据验的** —— 什么数据能让它露馅?就用那个数据验
5. **重复稳定性** —— 交互类连续 5 次
6. **残留与不确定**

|---|---|---|---|

### 🔴「刀没红」三分法(店主 05l 立,判据自述必答)

刀砍下去没红,**有三种可能,必须逐个排掉再下结论**:

| 可能 | 怎么认出来 | 怎么办 |
|---|---|---|
| **① 判据废** | 换个真会发生的病,判据照样绿 | 重写判据(黑名单 → 白名单往往就是解) |
| **② 刀砍空** | 砍的那个分支这条路根本走不到 | 改砍**机制本身**,不砍守卫 |
| **③ 防线还在** | 另有一层在挡(别处的过滤 / 唯一索引 / 上游校验) | **这是好事**,但要写明是哪一层挡的 |

案底(05k):待审跨店那把刀两轮没红 —— ①是黑名单判据被 200 条上限挡住,
②隔离其实两层守(SQL 一层、全录读口一层),只砍一层不漏。
**「刀没红」和「刀没落」从现象上分不出来,不许直接当"没问题"记账。**

## 二、裁 #37 —— `data-scope.mjs`:环境变量排在路径前面,**改**

这是我踩坑时查出来的。文件抬头是你自己写的这句:

> 这台服务往哪个库写 —— **按库文件的绝对路径判,不按环境变量的一句话**
> …… 病根不是「没白名单」,是「有默认值,所以打错了不报错」
> …… 只要谁设了 `LL_TEST_DATA=1`,那道门就开了 —— **一个环境变量顶掉了全部保护**

而 `scopeOf()` 的第一行是:

```
if (env.NODE_ENV === 'production' || env.RAILWAY_ENVIRONMENT) return 'production'
```

**环境变量排在路径判据前面。** 现测后果:回归临时库 `/tmp/ll-ci-data.XXXX` 被判成 `production`,
护栏拒跑,整轮回归起不来 —— 跟这个文件自己立的规矩正好相反。

**方向是失败朝安全那边**(拒绝跑,不是放行),所以**不是安全洞**,是口径自相矛盾 + 谁的 shell 里有那个变量谁就跑不了回归。

**改法**:路径判据在前,环境变量在后 ——
先按路径判 `ci` / `sandbox` / `local`,**判得出就用路径的结论**;判不出(`unknown`)再看环境变量。

**但不许朝松的方向改**:`legacyScope` 里「只有 `ci` 才是 `test`」那一条**原样不动**。

**判据两条**:
- **造病**:`NODE_ENV=production` + CI 临时库路径 → `scopeOf` 必须是 `ci`。**先证它现在是红的**(现在返回 `production`)。
- **反向守**:生产库路径 + 不设任何环境变量 → **仍然不是 `test`**(证明这次改动没把门改松)。

**还有一层,我核到这里才发现,这一条比上面那条更要紧:**

`apps/api/test-noshow-aftersales.mjs:3857` 有一条判据,原话是:

> `㋙C③ 本机库/沙箱库都判为 live,只有回归临时库是 test(按**库路径**判,不看环境变量)`

**它一次都没喂过环境变量** —— 三次调用喂的都是 `{}`。
「不看环境变量」这句话,它**从来没量过**。

而下一条 `㋙C③c` 反过来把「环境变量说了算」**写成了预期**:

```
scopeOf(L, { RAILWAY_ENVIRONMENT: 'x' }) === 'production'
```

也就是:**同一个文件里,一条判据的话和另一条判据的预期是相反的**,
而说话那条因为没喂参数,永远绿。

**这是「判据说的和判据量的不是一回事」** —— J-39 / J-40 同族。

**所以 §二 要连着改三处:**

- `scopeOf`:路径在前(`ci` / `sandbox` / `local` 判得出就用路径的结论),
  **只有 `unknown` 才看 `NODE_ENV` / `RAILWAY_ENVIRONMENT`** ——
  真生产在 Railway 上路径本来就是 `unknown`,这一支保留是对的,**只是不该排在前面**。
- `㋙C③`:**真喂 `{ NODE_ENV: 'production' }`**,断言三个路径的结论**不变**。先证它现在是红的。
- `㋙C③c`:改成「环境变量只在 `unknown` 路径上说了算」——
  `scopeOf(未知路径, { RAILWAY_ENVIRONMENT: 'x' }) === 'production'` 要绿,
  `scopeOf(本机库路径, { RAILWAY_ENVIRONMENT: 'x' })` **必须仍是 `local`**。

## 一 🔴🔴 第一嫌疑:`run-all-tests.sh:13–18` 那条「不许接管道」的判据

### 量出来的

**`ci.yml:26`**:`run: bash apps/api/run-all-tests.sh`
**`run-all-tests.sh:13–18`**:
```bash
if [ ! -t 1 ] && [ -p /dev/stdout ]; then
  echo '🔴 别把这把脚本接进管道…' >&2
  ...
  [ "${PIPE_OK:-0}" = "1" ] || exit 2
fi
```

🔴 **我在一个 Linux 环境里现测了这两个条件**:
```
/dev/stdout -> /proc/self/fd/1
[ -t 1 ]           终端? no
[ -p /dev/stdout ] 管道? YES   → 条件成立 → exit 2
```

**而 26 秒这个数正好对上**:checkout ~3s + setup-node ~3s + `apt-get update && install librsvg2-bin fonts-noto-cjk` ~18s + **step 5 秒退** ≈ **26s**。
**`exit 2` ≠ 0 ⇒ job failure。**

## 二 🟢 批:改 `ci.yml` 一行,再推一次。一箭三雕

**改法(照脚本注释里写的跑法)**:
```yaml
      - name: Run all regression suites
        run: |
          set +e
          bash apps/api/run-all-tests.sh > ci.log 2>&1
          rc=$?
          cat ci.log
          exit $rc
```
🔴 **三处不许省**:`set +e`(否则重定向那行红了就直接退,`cat` 不到)· **`cat ci.log` 在 `exit` 之前** · **`exit $rc` 保留真实退出码,不许吞**。

### 为什么批,三条

1. **不动产品代码** —— 只改 CI 怎么跑那一行。
2. 🔴 **它同时解决了你那个「日志 403 看不到」的问题** —— **日志会直接打进 Actions 的输出里,店主不用去弄令牌。**
3. **不动生产**:CI 红 → Railway 不放行(和昨晚一样);CI 绿 → 部署,**而那是店主昨晚已经批过的那一次推的延续,不是新决定。**

### 两面验,改完先在本机做

- **正向**:改法落地后,用**管道形态**跑一次(`bash apps/api/run-all-tests.sh | cat` 那种)—— **必须仍然跑得起来**(因为已经重定向到文件,不再是管道)。
- 🔴 **反向**:把跑法改回 `bash apps/api/run-all-tests.sh` 原样、在管道下跑 —— **必须 exit 2 红**。
**两面都过,才算证明了这条判据确实会在管道下咬人。**(J-58⑥)

🔴 **CI 绿 → Railway 部署 → 09u §二 第 4 步那六项核验照跑,任何一项不过:停、只读、进队列、不自己修不自己回滚。**

## 三 🔴 我读代码顺手挖出两件,一件比 CI 红更坏

### 🔴🔴 (1) `tools/pre-regression.sh:23,25` —— 一条护栏在 Linux 上 24 天一直是假绿

```bash
BEFORE=$(md5 -q "handoff/写库脚本护栏三列清单.md" 2>/dev/null || echo none)
node tools/gen-guard-checklist.mjs --write >/dev/null 2>&1
AFTER=$(md5 -q "handoff/写库脚本护栏三列清单.md" 2>/dev/null || echo none)
if [ "$BEFORE" = "$AFTER" ]; then say "护栏三列清单" "✅ 已是最新"
```

**`md5 -q` 是 macOS 的命令。Linux 上没有 `md5`,只有 `md5sum`。**
⇒ 在 Linux 上两次都报错 → 被 `2>/dev/null` 吞掉 → **两边都回落成 `none`** ⇒ `BEFORE = AFTER` ⇒ **永远报「✅ 已是最新」。**

🔴 **这不是「会让 CI 红」,这是更坏的一种:它在 CI 上永远通过。**
**而 `pre-regression.sh` 确实在 CI 路径上** —— `run-all-tests.sh:107` 调它。
🔴 **这是 J-53② 的教科书实例**(兜底成空不产生能工作的默认值,只产生一个不报错的失败),**而且它长在一条安全护栏上。**

**要做的**:改成两边都能跑的写法(`md5sum` 优先、回落 `md5 -q`,**两个都没有就当场红,不许回落成 `none`**),**并加两面断言**:清单变了必须红 · 清单没变必须绿。**🔴 还要加一条:`md5`/`md5sum` 都取不到时必须红,不许静默。**

### ✅ (2) `tools/knife-ratchet-attr.sh` 四处 `sed -i ''` —— 排除

`sed -i ''` 是 macOS 语法,GNU sed 会把 `''` 当脚本参数 → 会错。
**但我查了:这个脚本不在 CI 路径上**(`run-all-tests.sh` 与 `ci.yml` 都没调它)。**不影响这次。列进推后待办即可。**

### 🟡 (3) `verify-restored.sh` 的 mktemp —— 你修对了,但大概率不是这次的原因

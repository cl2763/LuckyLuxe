## 1. 范围
- 商家端小程序：「作品」页新入口「拍照姿势卡」；姿势卡筛选页、卡片详情页；「AI 修图」选图 / 预设 / 处理中 / 结果页。
- 后端：修图任务接口 + 流水线 + 计费记录。
- 顾客端：**零改动**。网页商家端：本批不做（小程序先行）。

## 2. 姿势卡（纯前端 + COS）
1. `pose_cards.json` 原样进小程序包（33 条，< 20 KB）。字段：`id group name length shot style pose cam light bg avoid image samples[]`。
2. 33 张 PNG 转 webp（长边 1086，质量 82，每张 ≤ 100 KB）传 COS `pose-cards/{id}.webp`，`image` 字段改成真实 URL；COS 域名已在 downloadFile 白名单。列表用缩略（长边 480）另存 `pose-cards/thumb/{id}.webp`。
3. 筛选：三组 chips 单选，「风格」含「不限」；默认不选 = 按 A–E 分组展示全部 33 张。推荐规则写死前端：
   - 命中 = length 相等 且 shot 相等 且（style 相等 或 style=不限）；
   - 命中为 0 时降级：去掉 style 再匹配；仍为 0 → 提示「换个组合试试」并展示同 shot 的全部卡；
   - 推荐条上的文案按 length：短/中 →「短甲用俯拍最显手型」；长/超长尖 →「长甲用平视最显长度」。
4. 卡片详情：主图 + 三个标签 + 六格（手怎么摆 / 机位 / 光 / 背景 / 避坑 / 适合），角落固定一行「示意图」；底部两按钮：
   - 「用手机原相机拍」= `wx.chooseMedia({count:4, mediaType:['image'], sourceType:['camera'], sizeType:['original']})`，拍完带图跳 AI 修图页，带 `sourceCardId`；
   - 「选图去修图」= 同接口 `sourceType:['album']`。
   - **不使用 `<camera>` 组件。**
5. 埋点（本地日志即可，不建表）：卡片打开、按钮点击、sourceCardId 进入修图；日后统计哪张卡最常用。

## 3. AI 修图
### 3.1 前端
- 选图区：≤ 4 张，来自姿势卡带入或 `chooseMedia`；每张先做**端侧压缩**（长边 ≤ 2048，JPG 质量 90）再上传 COS 临时目录 `retouch/in/{jobId}/{n}.jpg`。HEIC 由 chooseMedia 在 iOS 上自动转 JPG，后端仍要兜底（§3.3）。
- 预设：六条，多选；`冷白皮` 与 `暖奶油` 互斥（选一个另一个置灰）；至少选一条才能提交。
- 顶栏显示本店剩余张数；为 0 时按钮置灰并给「联系店主开通」。
- 处理中：进度条 + 「可以先返回，修好了通知你」；失败：原图不动、可重试或跳过、不计张数。
- 结果页：左右拖动对比（原图 vs 修后），双指放大；「用修后图」→ 选去向：作品上墙 / 顾客小记 / 保存到相册；「重选预设」回到预设页。
- 权限：技师、店主可见；顾客端无入口。

### 3.2 接口
- `POST /api/ai/retouch` `{ imageUrls[1..4], presetIds[1..5], sourceCardId? }` → `{ jobId }`
- `GET /api/ai/retouch/:jobId` → `{ status: queued|running|done|partial|failed, items:[{ index, status, resultUrl?, error? }], usedCount }`
- `POST /api/ai/retouch/:jobId/apply` `{ index, target: work|note|album, targetId? }` → 把修后图落到作品/小记（保存相册由前端 `saveImageToPhotosAlbum`）。
- 鉴权沿用现有店 + 角色；跨店隔离按 D132 口径（`dataScope` 按店）。

### 3.3 后端流水线（每张图）
1. **归一化**：HEIC→JPG、EXIF 方向转正、长边 ≤ 4096、去除元数据。
2. **prompt 组装**：固定前缀（绝对不改清单）+ 选中预设按固定顺序 `p6 白平衡 → p3 暗光救回 → p4 去反光 → p1/p2 肤色 → p5 背景虚化` 各自的段落拼成**一条** + 固定后缀。前缀/后缀/六段文本全部放配置文件 `config/retouch-presets.json`，**内容先用 12a 第 1.2 节的版本**，12a 回执后店主定稿再改配置。
3. **调模型**：`config/retouch-model.json` → `{ provider:"ark", model:"doubao-seedream-4-5-251128", size:"2K", watermark:false }`，一张只出一张；钥匙读 `ARK_API_KEY` 环境变量（Railway 上配，行首 trim）。超时 90 秒，失败重试 1 次。
4. **甲面贴回 + 超分**：按 12a PoC 结论决定开不开；先做成流水线里的可开关步骤（默认关），PoC 说拼接边自然再开。
5. 结果存 COS `retouch/out/{jobId}/{n}.jpg`；写表 `ai_retouch_jobs`（店、操作人、jobId、张数、presetIds、model、单价、耗时、成败、sourceCardId、createdAt）。
6. **计费**：按成功张数扣本店额度；失败不扣。额度与「前 3 个月免费」口径接现有 AI 计费配置，本批只记账不收款。

### 3.4 「只保留修后那一张」的实现口径（店主 09-22 澄清后）
- 这是**快捷入口**的口径：从姿势卡 / 「AI 快速修图」进来修完，作品墙、小记、相册只落修后图，界面不展示原图、不做双份。
- **AI 图库**（二级入口，本批不做）按此前定好的口径：**修前 + 修后都保存、成对展示**。所以数据层**不删原图**：`retouch/in/` 原图与 `retouch/out/` 修后图都永久保留并在 `ai_retouch_jobs` 里成对关联（`originalUrl` / `resultUrl`），供 AI 图库日后直接读。两个入口读同一张表，只是快捷入口的界面只取 `resultUrl`。
- 「用修后图」落到作品/小记时，记录上带 `retouchJobId` + `index`，AI 图库以后能反查到原图。
- 不设 COS 生命周期自动清理。

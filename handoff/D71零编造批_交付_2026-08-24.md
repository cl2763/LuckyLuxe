且危害更重:店主可能据此判断渠道效果做投放决策。按零回落律改为「—」或「未知来源」,
并全仓扫同类"编造展示值"的地方(哈希/随机/取模生成的任何用户可见内容),一并列清单。」

## 一、类定义(按机制,不按长相)

**编造展示值 = 用哈希 / 随机 / 取模 / 写死权重造出来的、当作"事实"给人看的内容。**

不算的:`randomId` / 单号 / token / 会话 id / AI 出图随机种子 —— 那些是**标识符**,不是对某个事实的陈述。
分界线一句话:**这个值如果错了,会不会让人做出错误判断?** 会 → 属于本类。

## 三、怎么改的

- **后端唯一出口**:`apps/api/order-badges.mjs` 新增 `bookingSourceText(raw)` ——
  有真值说真值(库里存的中文渠道名直用;`owner_direct` 这类机器码翻成人话「老板直接排单」);
  **没值 → 「未记录来源」**;不认识的值**原样透出**(那也是真值),就是不编。
  `serializeBooking` 随单下发 `sourceText`,前端只渲染。
- **首页渠道卡**:改成按订单的 `sourceText` 分组计数,没记录的单独一条「未记录来源」;
  零订单时出空态,不再拿顾客数乘个系数凑一张图。

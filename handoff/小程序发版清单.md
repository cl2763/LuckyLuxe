# 小程序发版清单(上传/提审前逐项核)

> 目前一律**沙箱不发版**。这份清单是给将来第一次上传体验版/提审时用的,
> 每加一条外部依赖就往这里补一行,别等提审被拒了才想起来。

## 一、代码开关(每次上传前必查)

- [ ] `miniprogram/utils/api.js` 顶部 `USE_LOCAL_SANDBOX` 必须改回 **`false`**
      (沙盘开发时是 `true`,指向本机 4128;忘了改会把体验版指到你的电脑上)
- [ ] `LOCAL_API` 那行是临时调试用的,**不提交**;确认当前提交里它没被改成某个局域网 IP

## 二、小程序后台域名白名单

| 类型 | 需要加的域名 | 用在哪 |
|---|---|---|
| request 合法域名 | `https://www.luckyluxeatelier.com` | 所有 `/admin/*`、`/my/*` 接口 |
| **业务域名(web-view)** | `https://www.luckyluxeatelier.com` | **顾客签署页**(裁决③:`pages/sign` 用 web-view 包 `/sign/<单号>`) |
| downloadFile 合法域名 | `https://www.luckyluxeatelier.com` + COS 桶域名 | 签署快照 SVG / 作品图 |
| uploadFile 合法域名 | COS 桶域名 | 服务小记配图 |

> 业务域名要在小程序后台下载校验文件放到网站根目录才能通过验证 ——
> 这一步需要店主在微信公众平台操作,Code 做不了。
> 沙箱阶段:开发者工具勾「不校验合法域名、web-view(业务域名)…」即可验证。

## 三、发版前的功能自查

- [ ] 顾客签署页在真机上能打开、能签字(web-view 内的 canvas 签名板在 iOS/Android 都试一遍)
- [ ] 选券面板在 web-view 里能点开、换券后金额刷新
- [ ] 支付相关入口的状态文案(线上支付未开通时不出现「支付定金」按钮)
- [ ] 所有页面在深色模式/大字号下不塌版

## 四、账号与隐私

- [ ] 演示邮箱白名单登录(`ALLOW_DEMO_ADMIN_LOGIN`)在生产必须是关的
- [ ] 隐私协议与用户信息授权说明按微信新规填好(涉及手机号、相册)

## wxacode 真码接入(店主 2026-08-11 点名,上线前必验)
- 把沙盒占位码换成微信官方 `wxacode.getUnlimited` 真码时,**必须验证扫出来的码对应到具体那一张单**
  (与 qrFor 纯出码模式同源:码里带的是该单的一次性签署 token,不是通用入口)。
- 验法:开两张待签单 A/B → 各出码 → 互扫,断言 A 的码只进 A 的签署页;签完 A,B 的码仍有效且只进 B。

# 三裁交付(店主 2026-08-24)· A 爽约入状态机 / B 售后单出口 / C 真库清单

## 裁 A:爽约保留,但必须同样走状态机 + 爽约后动作收敛

**改前的实际情况(查明)**:`/no-show` 路由自己 UPDATE 主状态、自己判角色,**零前置校验** ——
已完成的单、已取消的单、售后中的单都能标一次爽约,标完主状态被改写成 CANCELLED、已入账收入被冲销。
另外网页端**根本没有爽约入口**(只有小程序有),两端能力不对等。

**改后**:
- `noShow` 进状态机动作表:`from: ['PENDING_PAYMENT','CONFIRMED']`(还没发生、也还没终结的单)、`ownerOnly`、售后中不许、`to: 'CANCELLED'`;扣费口径不变(仍按店配 `noShowForfeitPct` 算,算完作为字段交给状态机一起写)。
- 路由改薄壳:取参 → assertTransition → applyTransition,零状态判断。
- **爽约后动作收敛**:`disposeDeposit`(处置定金)也进状态机,金额进 label(后端出句)。网页与小程序原来**各写一份** `depositDisposal.state === 'pending'` 的显示条件,两份都删。
- 网页端补上爽约入口(页内弹层,守 D50「新增代码禁 confirm/alert」纪律,原因可填并进留痕)。

**途中抓到我自己上一刀的两个缺陷**(D70 那批引入,本批一并修):
1. 商家小程序操作面板会出**两颗一模一样的「标记爽约」**(allowedActions 一颗 + 老 if 链一颗)。
2. 面板里 cancel / openAfterSales / endAfterSales 点了**没反应** —— 动作项落到 `applyStatus(id, undefined)`。现在统一走 `runBookingAction`,发起/结束售后用可输入弹层收必填文字。

**实证**:网页实点爽约 → 主状态「已取消 · 已爽约」、动作收敛为空;造一张有定金收取记录的单再爽约 → 动作精确变成一颗「处置定金(CAD $50 待处置)」,点开就是既有二选一弹层。没有收取记录的单不出这颗(A⓪ 原规则保住)。

## 裁 B:三步链收掉,留痕挂到「结束售后」出口

- 后端三条路由(`after-sales/progress|resolve|close`)**整体下线**(留着等于留三个绕过合同④ 的后门);商家小程序三颗按钮、网页那份无人可达的弹层(D71-b)同批删。
- 「结束售后」现在:**处理结果必填**(状态机 `requiresNote`,空串 → 400 `RESULT_REQUIRED`,原措辞与错误码原样保留)+ 写一行 `after_sales_events`(kind=resolve,原文入库)+ 落 `after_sales_result`。
- **顺带修好一处**:改前 `endAfterSales` 不写事件行,售后三步卡的「已解决」那一节**时间显示「—」**;现在留痕跟着出口走,时间线补全(实拍:`● 已解决:已免费返工,顾客确认满意 | 08-24 09:58`)。
- 结果句同步到售后只读区与顾客端(同一份 `afterSalesProgress`,三端同源)。

**口径变化一处,请知悉**:`after_sales_status` 的 `processing`(处理中)是原来「写进展」置的,三步链收掉后新案子不再产生这个态,只有 `pending → resolved`。存量 processing 的单照常显示。要保留「写进展」再说一声,加进状态机做成一个动作即可。

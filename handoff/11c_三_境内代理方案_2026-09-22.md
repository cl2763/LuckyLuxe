## 三 机器没开的话,开一台要多大(建议,不是决定)

反向代理只转发,不跑业务:

```
规格   2 核 2G 最低档足够(它只做 TLS 终止 + 转发,不做计算)
地域   广州 / 上海 —— 离境内用户近
系统   Ubuntu 22.04 LTS
带宽   按量计费起步;真有量了再换包月
软件   Caddy(推荐)或 Nginx
```

**为什么推荐 Caddy 而不是 Nginx**:**证书自动签、自动续**(Let's Encrypt),配置只有几行。
Nginx 要另配 certbot + 定时续期 —— **多一个会在三个月后半夜过期的东西**。

## 四 配置形状(拿到域名之后照着填)

```
<你的备案域名> {
    reverse_proxy https://www.luckyluxeatelier.com {
        header_up Host {upstream_hostport}       # 让后端认得出自己
        header_up X-Forwarded-For {remote_host}
    }
    encode gzip
    log {
        output file /var/log/caddy/access.log
        format json
    }
}
```

🔴 **两条要在动手前定死的:**
1. **只转发必要路径还是全转发?** 我建议**先全转发**(小程序会打 `/auth/*` `/stores` `/services` `/availability` `/my/*` `/admin/*`,挑着转很容易漏)。
   **但 `/platform/*`(平台后台)建议不转** —— 那是你自己的运维口,没必要从境内暴露。
2. **超时**:预约/结算那几条会走 AI,给 60s;其余 30s。

## 五 接通之后要验的四条(现在先写死,到时照着验)

1. **从境内网络打得通** —— 🔴 **这一条我验不了**(我这台在境外链路上)。要你或小婕用手机流量访问一次
2. `https://<备案域名>/health` 回的 `commit` **与 Railway 上一致** —— 证明转发到的是同一份后端,不是缓存或别的东西
3. **小程序 request 合法域名**填的是备案域名,且 `USE_LOCAL_SANDBOX = false`(**机器闸已经立了**)
4. **证书链完整**(`curl -v` 不报 self-signed;境内浏览器不弹警告)

## 六 风险与边界

- 🔴 **Railway 那边一个字不动** —— 代理是腾讯云那台的事,后端不知道也不需要知道它的存在
- **多一跳就多一个会坏的地方**:代理挂了 = 境内全断,而 Railway 是好的。**所以第 2 条那个 commit 比对要进日常巡检**
- **证书三个月一续**:用 Caddy 就是自动的;这也是我不推荐 Nginx+certbot 的原因
- 🔴 **域名解析改动是对外可见的**:一旦 A 记录指过去,境内用户就走新路了。**建议先用一个临时子域(如 `api-test.<域名>`)验通,再切主域**

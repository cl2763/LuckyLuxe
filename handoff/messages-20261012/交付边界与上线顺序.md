# 消息功能：本批边界与上线顺序

## 本批功能
- 商家网页固定「消息」入口，小程序「管理 → 消息」。老板查看预约事件，员工查看本人工作提醒；读取历史、详情和已读状态。
- 顾客网页及小程序「我的 → 我的消息」支持详情、未读数和已读。原通知记录保持不变。
- 小程序订单详情增加主动订阅按钮；拒绝不阻断预约。375用于到店前提醒，461用于预约确认/变更。
- 模板ID来自店主提供的后台截图，字段已接入；这不等于已获发送授权或已送达。

## 当前限制（验收前保持可见）
- 站内消息展示最近100条；老板事件来源为现有预约提醒队列，员工为工作提醒表，不是全平台所有业务事件。
- 售后/财务/营销事件没有在本批全部新建；这些仍在后续清单。顾客消息详情目前不新增关联预约跳转，商家预约消息有跳转。
- 一次订阅不代表长期授权。确认消息消耗一份状态模板授权后，后续变更可能需要再次主动订阅。提醒是否最终送达以微信接口结果为准。
- 订阅入口仅在预约已确认后开放；待付款预约不展示可订阅按钮。新确认消息在已确认、尚未到店时间的预约上订阅时生成。
- 变更/到店提醒依赖门店现有通知规则及任务调度；规则关闭时不发送。
- 外部发送开关默认关闭。没有使用真实顾客进行推送测试。

## 按顺序完成
1. 本机代码和完整回归；新页面双端实点，失败项修复后重跑。
2. 冻结本批范围，核对正式运行时；获取新的一致性备份，在隔离副本重复启动核对旧表旧列与账本触发器。
3. 提供明确部署范围并取得生产写入批准；先发布兼容后端（微信发送仍关闭），核对版本和商家存量。
4. 上传新体验包；仅测试微信/星野测试预约开展实际订阅和送达联调。不能把模拟接口通过当成微信实际送达。
5. 真机完成后再提交审核；审核发布后按批准范围启用提醒。确认/拒绝/额度不足/返回正确门店订单均须有实测记录。

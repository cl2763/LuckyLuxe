## 红条① 顾客端写死 `STORE_ID`,非旗舰门店顾客根本约不了(也会下单串味)

`miniprogram/utils/api.js:13`
```js
const STORE_ID = 'store-ontario-01'      // 旗舰店 Lucky Luxe Ontario 的门店 id
```
用在三处真实请求上:
- `:460` `/availability?storeId=${STORE_ID}` —— 取可约时段
- `:474` `/technicians?storeId=${STORE_ID}` —— 取技师列表
- `:488` `createBooking` 请求体 `storeId: STORE_ID` —— **下单写入**

### 实测证据(本机 4128,租户 jics-nail = 小婕店)
| 请求 | storeId=store-jics-nail(真) | storeId=store-ontario-01(顾客端写死的) |
|---|---|---|
| `/technicians` | 4 位技师(小婕/翠花/苏苏/鹤辰) | `{"technicians":[]}` **空** |
| `/availability` | 15 个时段 | `{"error":{"code":"NOT_FOUND","message":"Store not found in this shop."}}` |

模拟器活体数据(小婕店顾客端 booking 页):`technicians = []`、`timeSlots = []`,
`refreshAvailability` 抛 `Store not found in this shop.`

### 后果
1. 非旗舰商家的顾客:**技师选不了、时段取不到**。
2. 以前不显形,是因为 `mock.timeSlots` 兜住 —— 顾客会看到一排**不存在的可约时间**,
   选一个照样能提交。
3. `createBooking` 带的是 `store-ontario-01`:**小婕店的预约有可能写到旗舰店名下**
   (CLAUDE.md 关键纪律 #7 那一类租户串味,只不过这次是顾客端方向)。

### 建议修法(需拍板,因为动"预约归属哪个门店"这个口径)
`STORE_ID` 常量删掉,storeId 一律取 `/stores` 下发的那一个(与币种 / 定金同一趟,
`storecurrency.js` 已有缓存机制可复用)。取不到就走 D17 失败态,不用兜底常量。

## 红条② 下单接口失败,顾客端照样跳「支付成功」并写一张本地假订单

`miniprogram/pages/checkout/index.js:140-192`
```js
} catch (error) {
  ...
  wx.showToast({ title: error.message || '后端暂不可用，已使用演示订单', icon: 'none' })
}
// ↓ catch 之后**没有 return**,继续往下走:
const order = { ..., paymentStatus: 'paid', transactionId: `mock_${now}`, ... }
storage.addOrder(order)                 // 本地存一张订单
storage.removeCartItems(...)            // 清空购物车
wx.navigateTo({ url: '/pages/payment-success/index?...' })   // 跳「支付成功」
```
后端一条都没建成,顾客看到的是**支付成功页 + 我的订单里一张 `paymentStatus:'paid'` 的单**,
购物车还被清空了。这是本轮发现里最严重的一处 —— 前面几处是显示假数据,这一处是
**让顾客相信自己约成功并付过款了**。

顺带:`:156` 技师名兜底写死 `'Mia Chen'`。

## 红条③ `createBooking` 接口没回 booking 就自己编一张

`miniprogram/utils/api.js:496-501`
```js
return data.booking || {
  service,
  technician: { id: technicianId, name: appointment.technicianName || 'Mia Chen' },
  depositCents: 5000,                                   // 写死 ¥50 定金
  finalDueCents: Math.max(0, service.price * 100 - 5000) // 自己算尾款
```

  本店真实定金是 `amountCents: 10000`(实测 `/stores` 下发),**编出来的是错的一半**。
- `:482` `technicianId = appointment.technicianId || 'tech-mia'` 同类写死兜底。

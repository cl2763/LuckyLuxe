## 二、四条现修

**D150 · 层层递进不许复读,递进到底才转人工。** 同一会话里顾客连续两句被判为同类(budget/question 同主题)→ 第二句必须换答法(换角度:按类型/按预算区间/问他在意什么),**同一句原文 0 次重复**;第三句仍同主题 → 「这个我帮您接人工问问」并转人工(这才是该转的点)。判据:六通套件通二三轮各一条;造病:去掉「换答法」→ 红。Code 之前留的「报价路 state 取不到上一句」→ 用 `conversation_messages` 最近 N 条(全录是唯一读口)取,不另开 state。

**D151 · 入站合并窗(静默等待)。** 顾客连发多句时,收到第一句后等 **8 秒**(可配 5–15),窗内再来的句子并成一条再答;窗内已在生成的回复作废不发;窗按最后一句刷新。**模拟器与企微入站同一处实现**(D153 的出口)。判据:三句间隔 1 秒 → 只出一条回复且三问都答;两句间隔 20 秒 → 两条回复;造病:窗置 0 → 三条回复 → 红。`/health` 报窗长。

**D152 · 报价顺序:折扣 → 原价 → 折后价。** 只在**本店配置里真有**的折扣(新客券 / 会员折扣 / 活动券,`coupons`/会员档)时才说,**没有就只说原价,不许编折扣**(事实闸);有则「新客首次可用 XX 券,原价 ¥398,券后 ¥348」。判据:北京店造一张新客券 → 回复含三段且数字对账;删券 → 只出原价;造病:没券也出「券后」→ 红。

**D153 · 模拟器 = 真通道(同一出口)。** 店主的问题要用结构答:`POST /admin/wechat/mock-chat-message`(模拟器)与企微回调入站**必须调用同一个 `handleInbound(tenant, externalUser, message)`**;静态白名单式判据:回复生成的调用点全仓只此一处,两入口各一行调用;造病:模拟器绕开 → 红。回执里向店主说一句人话:**同一句话,模拟器和微信客服里的答案一样;不一样的只是通道(图片/语音/多句)——多句由 D151 管,图片/语音等企微接通后另测。**

## 三、D149 · 平台运营控制台改密码登录(店主两次提出)

现在 `/platform` 只认 `OWNER_TOKEN`(令牌不是密码,店主觉得不便)。裁:
1. 新增**平台账号**表 `platform_accounts`(username / password_hash / must_change_password / status),登录页改为**用户名 + 密码**(与商家后台同一套哈希与会话机制,`platform_sessions`);「记住 30 天」照旧;
2. `OWNER_TOKEN` **只留给脚本/API**(`Authorization: Bearer`),网页登录不再显示令牌框;
3. 第一个平台账号由启动脚本/平台正门建(用户名 `platform-admin`,一次性密码进本地 `本地自查账号.txt`,首登强制改密;**生产上店主自己设**,入上线批);
4. 判据:密码登录 → 200 + 会话;错密码 401;令牌仍能打 API;令牌**不能**用于网页登录框;造病:去掉密码校验 → 红;

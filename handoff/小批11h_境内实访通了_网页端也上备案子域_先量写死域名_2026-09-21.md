## 一 店主问了一个架构问题,而且她记得是对的

> 「网页端现在都在 `www.luckyluxeatelier.com` 上。我的网页端是不是必须也搬到 `jingshengyouji.com`?你之前说不用新增域名,只要加点东西 —— 是这个意思吧?」

**她记得没错。而且 `api.` 这一条刚刚证明了那句话:没买新域名、没重新备案,只是在同一个备案主域下加了一条子域解析 + 一份 nginx 配置。**

### 先把两件事分开(这是她困惑的根)

| | 谁管 | 结论 |
|---|---|---|
| **小程序的 `request` 合法域名** | **微信硬规则**:必须备案域名 + HTTPS | 🟢 已解决 = `api.jingshengyouji.com` |
| **网页端(浏览器打开的顾客端/商家端)** | **微信这条规则管不着它** | 🔴 **不是「必须」,但应该搬,理由见下** |

### 为什么仍然应该搬(三条,按分量排)

1. 🔴 **将来在小程序里用 `web-view` 打开网页,「业务域名」也必须是备案域名。**
   她截图上「业务域名」同样是**未配置**。**现在不搬,那天还得搬,而且那天会更急。**
2. **境内速度**:后端在 Railway 美东。小婕和她的顾客在国内,**从国内直连美东,每一次点击都在等**。走北京那台代理会明显快。
3. **备案合规**:面向境内用户的网站挂在未备案域名上,**存在合规风险**。
   ⚠️ **我不是律师,这一条只陈述风险,不构成法律意见 —— 要确认请问专业人士或腾讯云备案客服。**

### 做法:和 `api.` 一模一样,几乎零成本

```
app.jingshengyouji.com   →  北京那台 nginx  →  同一个 Railway 后端
```
- **不买域名、不重新备案**(同一备案主域下的子域)
- **官网 `www.jingshengyouji.com` 一个字不动**,就像加 `api.` 时那样
- 证书用 certbot 扩子域,复用已有账户与 timer

### 🔴 而且两个入口并存,不是二选一

```
境内(小婕 + 她的顾客)   →  app.jingshengyouji.com
境外(半径 + 多伦多顾客)  →  www.luckyluxeatelier.com
                         ↘ 同一个后端 · 同一份数据 ↙
```
**她两家店在两个国家,这正好对上。不要为了统一而把加拿大那边绕到北京去。**

## 二 🔴 但动手之前,先量一件事:**代码里有多少地方把域名写死了**

**这是这一件唯一会出事的地方。** 两个域名指向同一个后端,凡是「写死了自己是哪个域名」的地方都会错。

**只量不改,列清单给我:**
1. **前端**:`apps/web/**` 里出现 `luckyluxeatelier` 的地方(绝对链接 / 跳转 / 回调)
2. **后端**:生成给外部用的**绝对 URL** 的地方 —— 签署链接、二维码、分享链接、邮件/短信里的链接、`Location` 跳转
3. **会话 / Cookie**:有没有写死 domain;两个域名各自登录会不会互相踢
4. **CORS / 同源**:有没有只放行一个域名的白名单
5. 🔴 **已经发出去的东西**:**过去生成的二维码 / 签署链接里如果写死了老域名,它们不会因为加了新域名就改变** —— **这一条单独列,因为它影响的是已经在顾客手里的东西**

**清单出来我再裁「怎么改」。不许先改后报。**

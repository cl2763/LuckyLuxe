## 一、🔴 D137 · 七条 `_tenant_fill` 触发器兜底回落旗舰店(跨租户红线族)

我读了触发器体(`local-server.mjs:17713–17735`,本机库与沙箱库 `sqlite_master` 现查:**7/7 条含 `'lucky-luxe'`**):

```
COALESCE((SELECT b.tenant_id FROM bookings b WHERE b.id = NEW.booking_id), 'lucky-luxe')
```

父表找不到(`booking_id` 为空或指错)→ **静默落旗舰店**。再往上几行还有每次启动都跑的 `UPDATE <表> SET tenant_id='lucky-luxe' WHERE tenant_id IS NULL`——任何一行 NULL,下次开机就归你店。这就是 D126/D130/D131 同一根子(有默认值、打错了不报错),只是从列默认值换成了触发器和回填。你 04f 新立的判据「可空租户列必须有落值触发器」正好把它当成合规放过了——**判据要改成「落值触发器不许有常量兜底」**。

**修法**(七条同族一次改):
1. 触发器改成:能从父表解出就填;解不出 → `RAISE(ABORT, 'TENANT_UNRESOLVED')`,整行不落(AFTER INSERT 里 RAISE 会回滚这次插入);
2. 开机那七条 `UPDATE … WHERE tenant_id IS NULL` 改成**只报数不改值**:有 NULL 行就 `console.warn` + 计数进 `/health.tenantNullRows`,由人处置(三库现查先报数);
3. 判据:静态——`sqlite_master` 里所有 `%_tenant_fill%` 触发器 SQL **不含 `'lucky-luxe'` 与 `DEFAULT_TENANT_ID`**(白名单式,0 处);行为——插一行 `payments` 带不存在的 `booking_id` → 必须失败,不得出现在任何租户下;正向——带真 booking 的插入落到该 booking 的租户;
4. 造病:把一条触发器改回 COALESCE 兜底 → 静态红 + 行为红;
5. 三库 `tenant_id IS NULL` 逐表报数(生产只读)。

## 二、立刀:重建型迁移必先备份

凡是 DROP/CREATE 重建表的迁移(现在两处:`dropTenantDefaults`、`schema-unique-rebuild`),**开机路径也必须先复制库文件**到同目录 `pre-<迁移名>-<时间戳>`,路径打进启动日志;没有要处置的表时不备份(空操作不留垃圾)。判据:临时库造一张带 DEFAULT 的表 → 起服 → 备份文件存在且大小等于起服前的库;造病:去掉备份那一行 → 红。同批把这次的账补上:本机库与沙箱库各做一份**现状备份**(`post-dropdefault-…`),写进对照表。

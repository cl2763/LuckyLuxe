## 三、② 网页端五块(`8d00e7f`)

### 屏 4d 员工管理五页签
计时排班｜技师业绩｜业绩目标｜薪资方案｜账号管理,按使用频率排,**一律纯文字无 emoji**(📅 📈 💰 ⋯ 👤 📝 全部去掉)。后三签老板专属,员工登录时整个隐藏。

- **业绩目标**:每人两组段选 ——「设置」= 目标怎么定(总目标/分项),「显示」= 员工端看什么(仅总进度/含分项)。选「总目标」时卡耗/单量两格自动收起。底部写明系统默认与「显示=仅总进度时员工端整页不出现分项来源」。
- **薪资方案**:全店默认 + 每人一行(模板名 + 编辑),点开即既有编辑器。工资试算仍留财务。
- **账号管理**:每人一行行内按钮(生成 / 重置密码 / 停用启用)。

### 财务区新增两签(都无 emoji)
- **日结**(屏 1 下半):日期导航 + 待分配单折叠卡(主/副 + 各自项目编号 + 比例输入 + 查看签署单 / 发起更正 / 保存分配)+ 技师汇总表(单数/业绩/卡耗/冲卡/目标,达标绿标、未达标显示差额)+ 价档异常与免卸笔数 + blocker 黄条 + 确认日结 / 重开(重开必须写原因)。
- **趋势**(P2.4):日/周/月/年四种粒度柱状图(达标月份柱子变绿)+ 环比 + 明细表(收入/支出/净利/单量/客单/充值/耗卡/目标)。

### 屏 1b 金额更正页
上半是顾客已签存档单(只读带「不可修改」标),下半填更正后合计 + 原因(必填,前端先拦一道)。文案写明「原签署单保持原样,追加更正记录,储值差额系统自动补配」。走 `/admin/settlements/:id/amend`,不碰原单。

### 屏 2 工资试算页改造
- **归属备注区整块删掉**(v6 定稿:代付不涉技师业绩归属,且日结已逐日确认过)。待写小记与核查按钮保留。
- 顶部加**日结业绩模块**:逐日列出单数/金额/待分配数;未确认的给「去日结」按钮(点了直接切到日结板块并定位到那天),已确认的给绿标。
- 有未日结的天 → 黄条「本月有 N 天未日结,试算暂不含这几天业绩」,且**锁定按钮禁用**(设计图「需全部日结完成」)。
- 一天都没日结过时(旗舰店现状)→ 黄条解释「业绩显示为 0 是正常的,口径已改为已确认日结累加,要走完 结算 → 签署 → 日结 才有数」。这是你交代要覆盖的那条提示。

### 金额红线
两个新面板都不算钱。分成比例是老板输入,金额由后端算好回传;趋势柱高只是画图比例,所有数字照后端返回值显示。

## 八、两处顺带修的缺陷

1. **日结按比例分成保存不了**。`/admin/settlements/:id/allocate` 只认 `shareCents`,而两端 UI 填的是**比例**。要么让客户端算钱(破金额红线),要么日结根本走不通。改成**后端按比例折算、末行吃余数**,保证「合计正好等于单额」在按比例填写时也成立;老写法仍兼容。`test-daily-close` 41 → 44。
2. **小程序「今天」用的是设备时钟**。店在多伦多、人在国内时设备已跨到明天,点「今天」会跳到还没发生的一天,看着像单全没了 —— 与 CLAUDE.md「所有『今天』按门店时区算」冲突。新增 `utils/storeclock.js`,今天/本月一律取门店时区口径。

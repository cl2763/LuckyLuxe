## 三、② 网页端五块(`8d00e7f`)

### 屏 4d 员工管理五页签
计时排班｜技师业绩｜业绩目标｜薪资方案｜账号管理,按使用频率排,**一律纯文字无 emoji**(📅 📈 💰 ⋯ 👤 📝 全部去掉)。后三签老板专属,员工登录时整个隐藏。

- **业绩目标**:每人两组段选 ——「设置」= 目标怎么定(总目标/分项),「显示」= 员工端看什么(仅总进度/含分项)。选「总目标」时卡耗/单量两格自动收起。底部写明系统默认与「显示=仅总进度时员工端整页不出现分项来源」。
- **薪资方案**:全店默认 + 每人一行(模板名 + 编辑),点开即既有编辑器。工资试算仍留财务。
- **账号管理**:每人一行行内按钮(生成 / 重置密码 / 停用启用)。

### 财务区新增两签(都无 emoji)
- **日结**(屏 1 下半):日期导航 + 待分配单折叠卡(主/副 + 各自项目编号 + 比例输入 + 查看签署单 / 发起更正 / 保存分配)+ 技师汇总表(单数/业绩/卡耗/冲卡/目标,达标绿标、未达标显示差额)+ 价档异常与免卸笔数 + blocker 黄条 + 确认日结 / 重开(重开必须写原因)。
- **趋势**(P2.4):日/周/月/年四种粒度柱状图(达标月份柱子变绿)+ 环比 + 明细表(收入/支出/净利/单量/客单/充值/耗卡/目标)。

### 屏 1b 金额更正页
上半是顾客已签存档单(只读带「不可修改」标),下半填更正后合计 + 原因(必填,前端先拦一道)。文案写明「原签署单保持原样,追加更正记录,储值差额系统自动补配」。走 `/admin/settlements/:id/amend`,不碰原单。

### 屏 2 工资试算页改造
- **归属备注区整块删掉**(v6 定稿:代付不涉技师业绩归属,且日结已逐日确认过)。待写小记与核查按钮保留。
- 顶部加**日结业绩模块**:逐日列出单数/金额/待分配数;未确认的给「去日结」按钮(点了直接切到日结板块并定位到那天),已确认的给绿标。
- 有未日结的天 → 黄条「本月有 N 天未日结,试算暂不含这几天业绩」,且**锁定按钮禁用**(设计图「需全部日结完成」)。
- 一天都没日结过时(旗舰店现状)→ 黄条解释「业绩显示为 0 是正常的,口径已改为已确认日结累加,要走完 结算 → 签署 → 日结 才有数」。这是你交代要覆盖的那条提示。

### 金额红线
两个新面板都不算钱。分成比例是老板输入,金额由后端算好回传;趋势柱高只是画图比例,所有数字照后端返回值显示。

基准:《技师业绩可视化_UI设计图_2026-08-08.html》v2。**本轮交付 V1 + V4(网页端)与 V3 的后端部分;V2 与 V3 的小程序界面随 ③ 小程序端一起做** —— 它们要落在「小程序员工管理板块化」上,而那套板块(4a/4b/4c)是 ③ 的内容,现在还不存在,提前做会落在一个没有的骨架上。

### 屏 V1 技师业绩(网页)
新端点 `GET /admin/perf-ranking?metric=perf|orders|recharge&period=day|month`。

**口径红线怎么落实的**:排行走 `monthPerfFromCloses` / `dayPerfFromCloses` —— 和工资试算是**同一个函数**,不是"两套算法算出一样的数"。`test-perf-viz` 里逐人断言「排行 perfCents === 工资试算 perfCents」,还有一条在日结之前先跑一次,确认排行全 0(未日结不计入)。冲卡也只统计已确认日结那几天的充值,不会出现「业绩没算这天、冲卡却算了」的错位。

「员工管理 → 技师业绩」顶部两张卡:业绩排行(三维度 × 本日/本月)+ 目标进度。设计图的硬要求都照做了 —— **金额在条外右列,进度条里不压任何文字**;条宽用后端给的 `barPct`,前端不算钱。没设目标的人显示「未设目标 · 去『业绩目标』页签设置」,**不画 0% 的条**。

按此前的修正指令,**技师业绩行内不再有薪资/账号操作**(各自成签了),`data-tech-more` 的展开面板与处理器一并删掉。

### 屏 V3 的后端部分
`/admin/my-performance` 的 hero 增 `gapCents` / `hitTarget` —— 「还差 X 达标」的数也由后端给,前端不减。没设目标时 `hasTarget=false` 且 `pct`/`gapCents` 都是 null,整块不显示。`total_only` 的裁剪不受影响(进度条照给,分项仍然全页不下发),有断言锁住。

### 屏 V4 财务密码卡(网页)

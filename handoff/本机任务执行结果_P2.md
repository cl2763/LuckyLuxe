# 十一、结算单用券 + 自定义发放(2026-08-09,设计图《结算单用券》v3)

基准:桌面 handoff《结算单用券_UI设计图_2026-08-09.html》(C1/C2/C3 + 规则⓪–⑥)。全商户含旗舰店。

## 引擎:恒等式扩展 + 运行时强制

`assertSettlementInvariants` 从两条扩到四条,每次算钱返回前都跑一遍(算错直接 500,不是靠自觉):

```
档位优惠 ≡ 原价合计 − 档位小计
共优惠   ≡ 档位优惠 + 券抵扣        ← 设计图「共优惠(含券)」,拆行显示
应收     ≡ 档位小计 − 定金 − 券
分成基数 ≡ 应收 + 券                ← 券是店铺让利,不扣技师(规则③)
```

**券为 0 时四条退化成 08-08 的老两条**,存量行为逐分不变 —— 老单不受影响,这是整批最要紧的一条兼容线。

设计图算例逐分复现(测试里锁死):原价 ¥680 / 档位小计 ¥394 / 定金 ¥100 / 券 ¥30 → **应收 ¥264**、共优惠(含券)¥316。

**规则落点**
- ① 券包归属卡主:`couponOptionsFor` 只读 `settlements.user_id`(卡主)的券包,代付单同理;被服务者的券根本不进列表(有断言)。
- ② 一单一张:`assertCouponFree` 连**别处待签的单**也算占用;严格模式下选了用不了的券,正式开单直接 400,**不会悄悄按无券算再让顾客签一个不一样的数**。
- ⑤ 核销时序:签字成功那一刻才 `status=used` + 写 `settlement_code`。签字前退出/改单,券一直是 active —— 「释放回券包」不需要额外动作,也就不存在忘记释放这回事。
- ⑤ 更正退券:`/amend` 带 `releaseCoupon` 时券回券包,并在券流水记 `released` + 单号 + 原因;**原签署单一分没动**(已签不可改,有断言)。
- 门槛按**档位小计**判、适用大类按明细行的 `category_id` 判,不满足=置灰 + 后端写好的原因文案。

## 需要店主拍板的一条(本批唯一推定)

**分成基数取的是「应收 + 券」,不是字面的「档位小计」。**
设计图规则③写的是「业绩按档位小计算」,而现行系统从 P2 起,业绩基数一直是**应收**(= 档位小计 − 定金),旗舰店那两张演示单就是这么算的(小计 ¥98、定金 ¥50、业绩基数 ¥48 → Ava Lin $67.20 / Coco $28.80)。
本批只做了店主明确要的那一半:**券不进基数**。定金要不要也不减业绩,是另一件事 —— 改了会动到已确认日结的历史数字(两店演示单要重新分配),所以没擅自改。
要改成严格「档位小计」(定金也不扣技师业绩)就说一句,`settlementPerfBaseCents` 一行的事,加一条迁移把历史单重算即可。

老板主页业绩大屏

设计图 · 2026-09-03 · 图=合同 · 三端落点:小程序商家端首页顶部(老板身份) · 网页后台「今天」页顶部 · 员工看到的仍是「我的业绩」

这张图管什么:老板一打开店的主页,先看到一个会轮播的大数字(五个指标轮着来),再看四张小牌,一眼知道店今天/本周/本月怎么样。不管什么:不是财务页、不是图表页、不导出;点任何数字只是跳到已有的财务/日结页。三端主页的其它部分(台面、小记、客服工作台)这张图不动,留给「三端主页重画」那张。

看图要点
  1. 一个大数字轮播:五个指标每 4 秒换一个(营业收入 → 现金业绩 → 总卡耗 → 新增持卡 → 到店人次),底部五个点表示轮到谁;点大数字暂停并切下一个,左右滑也能切。
  2. 四张小牌永远是「大数字之外的那四个」,大数字换了小牌跟着换——五个指标任何时刻都在屏上,只是有一个被放大。
  3. 对比句只说人话:「比昨日 +18%」「比上周同期 −2%」;上期是 0 就写「上期 0」,不显示 ∞ 或 NaN。上升绿、下降红、持平灰,带箭头不只靠颜色。
  4. 折线是近 7 天(本周/本月态为近 7 周/近 7 月)的同一指标,只有一条线,不要图例;末点加白圈强调。
  5. 截至行说真话:今日是「未日结,实时」;翻到已日结的日子写「已日结 ✓ 老板确认于 21:05」。
  6. 月目标 62%只在店设了目标时出现(财务目标已有);没设就整块不出现,不占位、不写"未设置"。
  7. 财务锁开着时,五个数字全部按「财务指标显隐 v4」那张图遮成 ••••,轮播照转,解锁口同一处。

默认第一个		当期服务收入(现付 + 耗卡)+ 产品销售;红字冲销当期冲减(N-5 口径)今日=财务页/日结页实时那同一个函数;已日结日=daily_closes 快照 revenue_cents。大屏今日营收必须 === 日结页今日营收比昨日 / 比上周同期至今 / 比上月同期至今

总卡耗当期储值消耗金额(pay_channel = stored_value)+ 次卡消耗次数(两个数:钱与次)储值走账本;次卡走次卡消耗记录(不折算成钱,次就是次)同上
新增持卡当期首次开卡的顾客数(储值首充或首买次卡),按顾客去重储值首充 = 该顾客首条充值记录落在当期;次卡同理绝对数:「+2」
到店人次当期到达「已到店 / 已完成」的预约数 + 现场开单数,按单去重台面同一状态机(到店/完成),不另立口径绝对数:「−2」

Code 落地前先现测答两问,再动手:①「充值/购卡收款」在账本里现在记的是哪个 category/pay_channel——现金业绩的过滤要对着真值写,不许猜;②次卡消耗记录在哪张表、有没有时间戳能落到「当期」。答不上来的那一格,大屏先不上那个数(不可用即不呈现),不许拿 0 顶。

三、数据契约(一份数据,两端渲染)

GET /admin/dashboard/pulse?period=today|week|month(老板权限)。服务端算好一切,两端只渲染,不再各自算一遍。

字段含义
asOf取数时刻(门店时区),截至行直接用
currency随店:CAD / CNY
settled{state:'realtime'} 或 {state:'closed', confirmedAt}
goal月目标达成:{pct};店没设目标则字段不存在(不是 null,不是 0)
metrics[]固定顺序五项:revenue · cash · cardBurn · newCards · visits;每项 {key, value, unit:'cents'|'count', extra?:{timecardUses}, prev, deltaPct|null, deltaAbs, spark:[7]};deltaPct 在 prev=0 时为 null,前端据此写「上期 0」
locked财务锁状态,true 时 value 一律不下发(遮掩在服务端,不在前端)

五、行为

动作结果
进入首页 / 下拉取一次 pulse;不自动轮询
点「今日 / 本周 / 本月」换 period 重取;折线单位随之变为 7 天 / 7 周 / 7 月
点大数字暂停轮播并切到下一个;再点继续
长按大数字或点小牌跳到对应的既有页面:营业收入/现金 → 财务页当期;卡耗 → 储值流水;新增持卡 → 客户库筛「新持卡」;到店人次 → 今日台面
员工身份登录不显示大屏;首页顶部仍是现有「我的业绩」入口
网页后台「今天」页顶部同一块,横向一行:大数字在左、四小牌在右、折线跟在大数字下;同一 payload,同一轮播

六、验收判据(锚字段与身份,不锚文案)

  1. 同口径:同一时刻,大屏 revenue.value === 日结页实时营收 === 财务页当期营收(三处调同一函数,判据用同一夹具三处比对)。
  2. 已日结日:period 落在已确认日期时,revenue.value === daily_closes.revenue_cents 快照。
  3. 顺序与数量:metrics 恒为五项、顺序固定;造病(少一项)必红。
  4. 分母为零:prev=0 → deltaPct === null,页面渲染「上期 0」节点存在、无 ∞/NaN 文本。
  5. 币种随店:镜像店 CAD、小婕店 CNY,两店对照。
  6. 财务锁:locked=true 时响应体不含任何 value;前端遮掩节点存在。
  7. 目标:未设目标时 goal 字段不存在且页面无目标节点;设了则 pct 与财务目标页一致。
  8. 三态:加载/空/错各自的真话节点存在(.pulse-loading / .pulse-empty / .pulse-error),且互斥。
  9. 两端同源:网页与小程序对同一 payload 渲染出的五个数字文本一致(去掉格式差异后)。
  10. 造态自证:每条判据先造病验红再放绿;截图七态:三 period × 实时/已日结 + 锁定态,每张附 DOM 证据。

七、明确不做

不做图表页、不做导出、不做自定义指标、不做多店汇总(每店各看各的)、不做自动刷新。这些如果将来要,另开一张图。

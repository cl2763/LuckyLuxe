## 二、造病验红 + 归因(含一处**对我自己的更正**)

### 刀 I-tz:门店时区不生效

把 `tenantTimezone()` 里读 `stores.timezone` 那一行短路(行数不变,棘轮不动),重跑:

```
not ok  ①d 时区逐店落档 :: B 期望Asia/Shanghai 实际America/Toronto | C 期望Asia/Shanghai 实际America/Toronto
not ok  ①e 加拿大档与两家境内档必须分属不同币种/时区
not ok  ②a 北京档 15:00 存进库是 07:00Z :: 实际 2026-09-07T19:00:00.000Z
not ok  ②c 同一句话、两家店 UTC 必须不同 :: A=19:00 C=19:00
not ok  ③c 提醒时刻反算回北京时间落在 06:00–20:00 :: 北京 01 点
```
**5 条红,每条都点得出是哪一处。** 还原 + 重跑 → 24 条回绿。

### 🔴 归因更正(我先说错了一句,现更正)

我第一次跑归因时报「既有两店判据看不见这把刀」。**这句是错的。**
我的过滤只认 `^not ok` 这一种失败写法,而 `test-tenant-timezone` 报失败用的是 `✗` 开头并当场中止——
它**咬住了**这把刀(`✗ 上海店时区 = Asia/Shanghai: America/Toronto`),是我的筛子漏了。

这条更正本身就是《判据三》的活例子:**我拿黑名单式的筛子去数「谁红了」,漏掉了没列举的那种红法。**

所以三店套件在时区这一项上是**第二层**,不是新层。它真正新增的是**两店结构上表达不出来的那三条**:
`①f`(B/C 本来就同币同时区,判据不许靠「它俩不同」凑绿)、
`④d`(同口径的另一家也看不见北京店的单)、
`⑤c`(三店地址两两零串味)。
**这三条今晚没有单独挨刀** —— 登记在 §三,下一批补。

### 逐行指纹刀(新工具自己先挨一刀)

在**库的副本**上把 `lucky-luxe` 一行既有数据 UPDATE 掉(不加行、不删行):

| 判据 | 结果 |
|---|---|
| 新的逐行指纹 | 🔴 `lucky-luxe · users · 行 74→74 · 指纹 b2ea…→f5fc…`(退出码 1) |
| 新的逐行指纹(第二刀,改一张既有预约的备注) | 🔴 `lucky-luxe · bookings · **旧行消失 1 行**(行 173→173)` |
| **归因:同一把刀喂给旧判据 `db-snapshot.mjs`** | ✅ **绿**(退出码 0)「逐表零差异 —— 「本库未动」这句话有证据支撑」 |

但《未动须有证》要的是「行也没被改」,这一格此前是空的。**登记为判据缺陷,建议编 J-29。**

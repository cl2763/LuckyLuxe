## 二 · 🔴 建表 / 加列 / 迁移 —— 会多出什么(照 09n 件 C 的口径)

### 建一张新表(不动任何现有表)

```sql
CREATE TABLE IF NOT EXISTS signed_docs (
  id TEXT PRIMARY KEY,
  tenant_id TEXT NOT NULL,
  user_id TEXT NOT NULL,              -- 🔴 挂顾客档案,不挂订单(口径①)
  doc_type TEXT NOT NULL,             -- 'rights' 权益书 | 'consent' 护理同意书 | 'other'
  title TEXT,                         -- doc_type='other' 时必填
  page_count INTEGER NOT NULL DEFAULT 0,
  status TEXT NOT NULL DEFAULT 'active',   -- 'active' | 'voided'   🔴 没有 'deleted'
  voided_at TEXT, voided_by TEXT, void_reason TEXT,   -- 口径②:作废要留痕
  created_by TEXT NOT NULL, created_at TEXT NOT NULL, updated_at TEXT NOT NULL
);
CREATE TABLE IF NOT EXISTS signed_doc_pages (
  id TEXT PRIMARY KEY,
  doc_id TEXT NOT NULL, tenant_id TEXT NOT NULL,
  page_no INTEGER NOT NULL,
  storage TEXT NOT NULL,              -- 'cos' | 'inline'(与签署快照同一套,不另立)
  url TEXT, inline_data TEXT, mime TEXT, bytes INTEGER,
  created_at TEXT NOT NULL
);
```

🔴 **`CREATE TABLE IF NOT EXISTS` 是静默失败器族**(判据一):表在但结构不同就**悄悄不建**。
**所以**:新表照常用它(全新表没有存量),**但必须配一条 `test-schema-consistency` 能看见的断言**
(空库新建 schema ≡ 老库跑完迁移后的 schema),**并且列一律走 `try/catch ALTER TABLE ADD COLUMN`**(纪律 8)。

## 四 · 文件存哪 · 谁能读 · 删不删得掉

### 存哪

**复用签署快照那一套,不另立**(`local-server.mjs:8658`):
- **首选 COS**(`cosPutObject`,key = `signed-docs/<tenantId>/<docId>/<pageNo>.<ext>`);
- **COS 没配 / 上传失败 → inline 入库**,`storage='inline'`(**绝不因存储故障拦住上传** —— 与签署那条同口径)。
- 🔴 **不落卷上的文件系统** —— 卷只放库;这一条与现有做法一致。

### 谁能读

| 谁 | 能不能 | 怎么守 |
|---|---|---|
| **店主(owner)** | ✅ 全店 | `requireAdmin` + 租户闸门 |
| **技师(staff)** | ✅ **只限自己服务过的顾客** | 🔴 **照抄小记那把锁**(`local-server.mjs:14524` 那段:不带 bookingId 时查 `bookings` 里有没有 `technician_id = 我 AND user_id = 他`,没有就 **404**)|
| **顾客端** | 🔴 **拿不到**(拍板:先不给看) | **公开接口上一个字都不加** —— 不是"加了再关",是**根本不加** |
| **别的租户** | 🔴 **拿不到** | 每条 SQL 都带 `tenant_id = currentTenantId()`;路由排在闸门之后 |

🔴 **读写两道闸(判据二)**:上面六个口里 **1/2/3 是写、4/5/6 是读**,
**两个方向各写一条断言**,不许只验一侧 —— `service_notes` 就是写口漏了整整一批(08-27 才补)。

### 删不删得掉

🔴 **删不掉。** 口径② 定死:**只能作废,且留痕**(`status='voided'` + `voided_at/by` + `void_reason` 必填)。
**没有任何 DELETE 路由**,而且建议**配一条触发器**(与账本 `*_no_delete` 那一族同姿态):
```sql
CREATE TRIGGER signed_docs_no_delete BEFORE DELETE ON signed_docs
  BEGIN SELECT RAISE(ABORT, '签字凭证不许删,只能作废'); END;
```
**判别式(J-71:在最低那一层守)**:**绕过界面、绕过路由、直接连库 DELETE —— 也删不掉。**

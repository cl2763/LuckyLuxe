## 一 · 事实本身(现读 `data-scope.mjs:29-44`)

```js
if (isCiDataDir(dir))               return 'ci'
if (/[/\\]sandbox-data$/.test(dir)) return 'sandbox'
if (/[/\\]local-data$/.test(dir))   return 'local'      // ← 生产库路径正好以 local-data 收尾
if (env.NODE_ENV === 'production' || env.RAILWAY_ENVIRONMENT) return 'production'
return 'unknown'
```

生产库在容器里是 `/app/apps/api/local-data/lucky-luxe.sqlite` ⇒ **第三条命中 ⇒ 返回 `'local'`,
`'production'` 那一支在生产上永远走不到。**

## 二 · 🔴 但为什么它没有变成一个洞:**全仓对库域的用法一律是白名单**

| 出口 | 集合 | 生产(被判 `local`)落在哪一侧 |
|---|---|---|
| `DEV_SCOPES`(`secret-gate.mjs:17`)| `{ci, sandbox}` | **不在** → 严格侧 |
| `DEMO_OK_SCOPES`(`data-scope.mjs:77`)| `{ci, sandbox}` | **不在** → 严格侧 |
| `legacyScope` 的 `'test'` | 只有 `ci` → `test` | 生产 = `live` → 护栏拒绝 |

**没有任何一处写成 `scope !== 'production'` 这种黑名单。**
所以「生产被判成 local」**每一处都落在「不是开发档 ⇒ 按真环境办」那一侧**。
🔴 **这不是运气,是 J-68 的结构**:尺子的误差方向被白名单锁死在对自己不利那一边。
**机械佐证**:全仓现扫 `=== 'local'` / `has('local')` / 清单里含 `'local'` 的写法 —— **0 处**
(排除 `local-data` / `local-server` / `localhost` / `localStorage` 这些同形不同义的名字)。

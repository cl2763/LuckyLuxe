```bash
# ① 先从**活着的那个进程**问出它到底开着哪个库(不硬编码路径 —— 见下)
curl -s https://www.luckyluxeatelier.com/health | node -e "let s='';process.stdin.on('data',d=>s+=d).on('end',()=>{const j=JSON.parse(s);console.log(j.dbFile&&j.dbFile.path||'(/health 没给路径 —— 停,别猜)')})"

# ② 用上一步那个路径做 VACUUM INTO 备份(**不是 cp**)

  env DBB_SRC=<①问出来的绝对路径> DBB_OUT=<同目录>/backup-before-push-<时间戳>.sqlite \
  node --experimental-sqlite -
```

🔴 **两处改法,各有各的案底**:

1. **路径不许硬编码。** 我原来写死 `/app/apps/api/local-data/lucky-luxe.sqlite`。
   而代码里那个路径是 **`DATA_DIR` 决定的**(`local-server.mjs:128`
   `process.env.DATA_DIR ? resolve(...) : join(__dirname,'local-data')`)——
   **`DATA_DIR` 一旦设成别处,我那条命令就会去备份一个不存在的文件,而它不会报错、只会备出个空的。**
   改成**从活着的进程自己那头问**(`/health` 的 `dbFile.path`)—— J-62②:从事实那头读回来。
   **问不出来就停,不许猜。**
2. 🔴 **`cp` 在 WAL 下无效。** `/health` 的 `dbConcurrency.journalMode` 现测就是 **`wal`**,
   而 `lsof` 现测那个进程同时开着 `.sqlite` / `.sqlite-wal` / `.sqlite-shm` 三个文件 ——
   **只 cp 主文件会得到一个缺了最近写入的、甚至打不开的半个库**。
   `tools/db-backup.mjs` 走 `VACUUM INTO` + **备份完当场打开验一次**。

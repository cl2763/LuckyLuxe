## 一 · 要查什么(方向按 09n §五 给的)

**D201 的形态**:不登录就能把一张 `PENDING_PAYMENT` 的单标成已付 ——
`payments.status → 'PAID'` 且 `bookings.status → 'CONFIRMED'`,**而店里没收到钱**。

**所以指纹要找的是**:**状态是 PAID、但没有任何真实收款凭证**的那些行。

🔴 **先证指纹唯一**(J-58⑨,我第 21 笔那一族):
`confirmMockPayment` 写的那一行长这样 —— `provider = 'MOCK'`,且 `transaction_id` 是它自己生成的。
**现读代码**:`UPDATE payments SET status='PAID', transaction_id=? … WHERE booking_id=? AND provider='MOCK'`。
⚠️ **但 `/payments/mock/confirm`(有门那条)写的是同一行、同一个 provider** ——
**两条路留下的痕迹一模一样,指纹分不开。**

> 🔴 **所以这次的答案不可能是「哪几行是被打的」,只能是「有多少行处在这个形态里」。**
> **我先把这句话说在前面,免得查出一个数之后被当成「被攻击了这么多次」。**

## 二 · 查询原文(四条,全部 `SELECT`)

```sql
-- ① 底数:payments 一共多少行,按 provider / status 分布
--    (J-58①:没有底数的 0 不算数;也让「MOCK 占比」一眼看得见)
SELECT provider, status, COUNT(*) AS n
FROM payments
GROUP BY provider, status
ORDER BY n DESC;

-- ② 形态行:PAID 且 provider='MOCK' —— 两条路(有门的 / 没门的)都会落进这里
--    按店分开(09n §五.2 要求两家真店各一个数)
SELECT b.tenant_id, COUNT(*) AS n
FROM payments p JOIN bookings b ON b.id = p.booking_id
WHERE p.status = 'PAID' AND p.provider = 'MOCK'
GROUP BY b.tenant_id
ORDER BY n DESC;

-- ③ 更窄一格:PAID 的单,却没有任何一条对应的收入账目行
--    (真收钱会在账本里留行;只标状态不会)
SELECT b.tenant_id, COUNT(*) AS n
FROM payments p
JOIN bookings b ON b.id = p.booking_id
WHERE p.status = 'PAID'
  AND NOT EXISTS (
    SELECT 1 FROM finance_transactions f
    WHERE f.tenant_id = b.tenant_id AND f.tags = b.id
  )
GROUP BY b.tenant_id
ORDER BY n DESC;

-- ④ bookings 侧对照:CONFIRMED 的单里,有多少条根本没有 payments 行
SELECT tenant_id,
       SUM(CASE WHEN status = 'CONFIRMED' THEN 1 ELSE 0 END) AS confirmed,
       SUM(CASE WHEN status = 'CONFIRMED'
                 AND id NOT IN (SELECT booking_id FROM payments WHERE booking_id IS NOT NULL)
                THEN 1 ELSE 0 END) AS confirmed_without_payment
FROM bookings
GROUP BY tenant_id
ORDER BY confirmed DESC;
```

**四条全是 `SELECT`** · 不建文件 · 不改 journal 模式 · 不带任何写。
**每一条都带底数或按店分组** —— 没有一个裸 0。

## 四 · 跑的时候怎么守(09n §五.4 / §五.5)

1. **只许 `SELECT`** —— 一个字的写都不许。
2. **非 0 立刻停,只报不动** —— 不删任何行、不改任何状态。
3. 报数时**先写库名与指纹**(绝对路径 + 字节数 + mtime + inode),J-64。
4. 🔴 **报出来的数不许被称作「被攻击次数」** —— 见 §一那句:两条路的痕迹分不开。
   能说的只有:**「处在这个形态里的行有多少」**,以及**「其中有多少没有对应的账目行」**。

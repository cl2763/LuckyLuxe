## 证据一:零余额 → 「到店收·差额自动」= 全额

实点「零余额客」那单 → 勾技师 → 支付构成(DOM 现测原文):
> `储值卡抵扣 勾了才烧余额`(无余额句)
> `→ 到店收 · 差额自动 现金/扫码/POS · 差额 CAD $198.00(其余支付方式结清后的余数,自动算)`
> 合计:`到店应收 CAD $198.00`

**差额 = 全额 $198** ✅(截图 1:顾客行「零余额客 138****0011 新客·未绑定」+ chips + 项目两栏)

## 证据二:有余额 → 勾储值,差额 = 合计 − 抵扣(两状态并排)

实点「有余额客」那单:

| | 勾储值**前** | 勾储值**后** |
|---|---|---|
| 储值行 | `储值卡抵扣 可用余额 CAD $500.00` | `✓ 储值卡抵扣 可用余额 CAD $500.00 → 本单抵 CAD $198.00` |
| 差额行 | `差额 CAD $198.00` | **`差额 CAD $0.00`** |
| 合计区 | — | `储值抵扣 −CAD $198.00` 行出现 |

**差额 198 − 198 = 0** ✅(金额全部后端算,前端零算术)

## 一问的证据:是不是所有商家都生效

**① 零租户硬编码(常驻断言)**:白名单式扫 `settlement-web.js` + `settlement-routes.mjs` 的租户字面量
(lucky-luxe / jics / 小婕 / demo-* / 店名,剥注释后),白名单**空** —— 塞一个当场红(变异已验:
塞 `'lucky-luxe'` → 重启 → 断言红,还原绿)。另一条:开单套件全程跑在**临时新建店**上,
新店全流程走通本身就是"不认店"的行为证明。

**② 两家不同店实测对照**(同一流程各开一单,同一套代码):

| | 开单走查店(CAD) | 开单对照店(CNY) |
|---|---|---|
| 项目行 | `✓ 精品单色 CAD $198.00` | `✓ 精品单色 ¥198` |
| 合计 | `到店应收 CAD $198.00` | `到店应收 ¥198` |
| 小数位规则 | 带 .00(CAD 配置) | 不带(CNY trimZeroDecimals)|
| 大类 | 各自建店时落的三大类 | 同左(各自的字典) |
| 落库 | `ZJ-20260829-3AUF` pending_sign | `ZJ-20260829-ZLA4` pending_sign |

连币符与小数位都各走各店的 `currencyDisplay` —— 一处硬编码都藏不住。

**③ 每个读配置的块,配置来自哪**:

| 块 | 配置来源(表 · 租户字段) |
|---|---|
| 价格档四档价 | `pricing_item_prices` / `services.*_price_cents` · `tenant_id` |
| 大类 chips | `service_categories` · `tenant_id` |
| 项目/加项 | `services` · `tenant_id` |
| 技师 chips | `technicians` · `tenant_id` |

## 二、🔴 D132 · 会话归店(口径裁定)

### 病(我读码,与你报的一致,再多两层)

1. `local-server.mjs:1641`:`conversationId = \`wecom:${externalUserId}\``,主键**不带租户**;`WHERE id = ?` 的读写口我数了 **14 处**(1574/1645/1664/1718/2118/2235/3747/4323/4349/4914/12002 …),没有一处带 `tenant_id`。
2. **更根上的一层——企微入站的租户从哪来**:`/wechat/customer-service/webhook`(11133–11137)用 `resolveTenant(req, query)`,即 **`x-tenant-id` 头或 `?tenantId=`**,拿不到就 `validTenantId` **回落默认租户(旗舰店)**。企微服务器不会发这个头;一个企业(一个 `WECOM_CORP_ID`)的客服回调 URL 只有一条,**按 URL 参数分店走不通**。真正能分店的是消息里的 **`open_kfid`**(每家店一个客服账号),它已经进了 `inbound.openKfid` 和 `wechat_conversations.open_kfid` 列,但**没有 open_kfid → 租户的映射**,也没人拿它定租户。
3. 「拿不到就回落默认」正是 D128/D130/D131 同一根子(**有默认值,打错了不报错**),这次落在了会话上。

### 口径(定了,不另出图;修复动的是身份口径,所以先写进这里再动代码)

| # | 口径 |
|---|---|
| ① 会话身份 | **会话 = (租户, 渠道, 外部用户)**。加唯一索引 `(tenant_id, provider, external_user_id)`;**新会话 id 形态 `wecom:<tenant_id>:<externalUserId>`**;存量行 id **不改**(quote_requests / reminder_tasks / ai_conversation_states 都挂着它,改 id 是连锁写),只补索引——本机库现查跨租户复用 0,零冲突 |
| ② 查找/创建 | 进线时按 **(租户, provider, external_user_id)** 找,不按 id 拼;找到用它的 id,找不到按新形态建。**唯一出口**一个函数,14 处 `WHERE id = ?` 的顾客侧读写全部改走它并带 `tenant_id = ?`;后台侧走现有 `assertStaffCanAccess…` 验租户(读写两道闸律) |
| ③ 企微租户来源 | **`open_kfid → 租户`** 映射:每店一条,存 `tenant_settings`(key `wecom_open_kfid`,值唯一,后台「门店设置 → 企微客服账号」一行,老板填;平台后台可代填)。webhook **只认这个映射**,不再看头/参数;**映射不到 = 拒收**(HTTP 200 回企微避免重试、内部记 `wecom_unrouted` 留痕一行:kfid、外部 id、时间——**不建会话、不落默认租户**)。**渠道未接通前(等可信 IP)这一段只落代码与判据,不联调** |
| ④ 默认回落 | 顾客侧(小程序 `/customer/*` 与 webhook)**不许回落默认租户**:缺失或无效 → `400 TENANT_REQUIRED`。**新刀先预判该红几处**:先 report-only 统计回归里顾客侧请求「没带 / 带了无效租户」各多少条,报数随回执,数看完我再放 fail-closed;webhook 那一条按 ③ 直接 fail-closed |
| ⑤ 演示种子 | `wecom:demo-chat-01/02` 那类改成新形态(带演示租户),否则多演示店会撞主键 |
| ⑥ 不做 | 不改存量 id;不做跨店合并会话;不做「同一人多店共享记录」——每店一份是既定口径 |

### 判据(落刀,不许只截图)

1. **两店同号**:租户 A、B 各用同一个 `externalUserId` 进线两轮 → 两行会话、各自 transcript 只有自己的、`quote state` 各归各;A 再进线一句,B 的行**逐字节不变**(这就是你探针那条病的反面)。
2. **读闸**:拿 B 的 conversationId 从 A 的租户上下文读/写 → 404/403,库不动。
3. **kfid 路由**:三条消息分别带 A 的 kfid、B 的 kfid、未映射 kfid → 落 A、落 B、`wecom_unrouted` +1 且会话表 +0。
4. **静态**:全仓 `FROM wechat_conversations … WHERE id = ?` 在顾客侧路径上 **0 处**不带租户(白名单式,同 D104 那把的形制);`INSERT INTO wechat_conversations` 必须显式 tenant_id(D131 刀已盯着)。
5. **造病**:把出口里的 `AND tenant_id = ?` 去掉 → 判据 1 的「B 逐字节不变」红 + 判据 2 红 + 静态红;把 kfid 映射改成回落默认 → 判据 3 第三条红。
6. **存量**:三库加索引前先查冲突数(报数);本机/沙箱条件迁移;**生产只读报**冲突数与 `wecom:` 行数,另批。

# D221 · 主体分割(手 + 甲面)选型 —— 三个候选,**等店主批,Code 不替**

立项依据:12f §四。皮肤层、甲面贴回、换背景贴回**三件卡在同一堵墙**上 ——
零依赖下做不出可靠的甲面分割(证据:12a_四 贴回 PoC 否定 + 本轮肤色掩膜在红甲/裸甲/暖背景上全面失效,
42 号掩膜占比 80.9% 把整张图都圈进去了)。

🔴 **先说一句最要紧的**:下面三个**没有一个能原生输出「指甲」这一类**。
公开可用的分割模型里,「手」是常见类,「指甲」不是。所以三个方案都是**组合方案**,
把「手/前景」和「指甲」分两步拿。这一点在批之前必须知道,不然会以为装一个模型就解决了。

🔴 **另一句**:下面的体积与耗时是**公开规格与通行经验值,我没有在这台机器上实测过**
(12a 禁装依赖,到本批为止)。要准数得先批准安装,我再跑基准并回报。

## 候选一 · MediaPipe Hand Landmarker(Google)

| | |
|---|---|
| 许可证 | **Apache-2.0**(可商用) |
| 体积 | **约 7 MB** |
| CPU 推理 | **约 10–30 ms / 张**(三者最快) |
| 能出「手」吗 | ✅ 出 **21 个手部关键点**,不是掩膜 —— 手的区域要由关键点凸包推出来 |
| 能出「指甲」吗 | ❌ 不能。只能由指尖关键点**推出指甲大致位置**,拿不到轮廓 |

**适合**:定位手、定位指尖(给下一步当种子点)、判断左右手与姿势。
**不适合**:直接当皮肤掩膜(凸包会把指甲和指缝一起圈进去,跟现在的毛病一样)。

## 候选二 · rembg(U²-Net 系)

| | |
|---|---|
| 许可证 | rembg **MIT**;u2net 权重 **Apache-2.0** |
| 体积 | u2netp **约 4.7 MB** / u2net **约 176 MB** |
| CPU 推理 | u2netp 约 **0.3–1 s**;u2net 约 **1–3 s** |
| 能出「手」吗 | ✅ 出**前景掩膜** —— 手连着指甲是一整块 |
| 能出「指甲」吗 | ❌ 不能,前景里分不出指甲 |

**适合**:**换背景贴回**那一步(12e §七 第 3 步)—— 它要的正是「主体 vs 背景」一整块。
**不适合**:皮肤层(分不出指甲,一磨就磨到甲面)。

## 候选三 · MobileSAM / SAM2-tiny(可提示分割)

| | |
|---|---|
| 许可证 | MobileSAM **Apache-2.0**;SAM2 **Apache-2.0**(权重条款需逐版确认) |
| 体积 | MobileSAM **约 40 MB**;SAM2-tiny 约 **150 MB** |
| CPU 推理 | MobileSAM 约 **1–2 s / 张**(给定提示点);SAM2-tiny 更慢 |
| 能出「手」吗 | ✅ 给提示点就能 |
| 能出「指甲」吗 | ✅ **给每个指尖一个提示点,能分出单片指甲** —— 三者里唯一能拿到甲面轮廓的 |

**适合**:甲面贴回、皮肤层(皮肤 = 主体 − 指甲)。
**代价**:要提示点 —— 提示点由候选一的指尖关键点给。

---

## 我的建议(**只是建议,批不批你定**)

**候选一 + 候选三 组合**:MediaPipe 出指尖关键点(7 MB / 30 ms)→ MobileSAM 按点分出每片指甲(40 MB / 1–2 s)。
- 手部皮肤掩膜 = 主体 − 指甲 —— 现在 42 号那种「整张图被圈进去」的毛病会消失
- 甲面掩膜拿到了,**甲面贴回**与**换背景贴回**都能做
- 合计约 **47 MB**,单张约 **1–2 秒**,两个都是 Apache-2.0
- **顾客照片全程不出本机**,不调任何第三方分割 API(12f §四 红线)

单用候选二只能解决换背景贴回那一件,解决不了皮肤层与甲面贴回。

## 🔴 不是全都要改 —— 分类原则(下批定)

这 66 处里有**合理的**,不能一刀切:
- `JSON.parse(…) catch { return {} }` —— 解析用户数据,坏了给空对象是对的
- `localStorage.removeItem(…) catch {}` —— 浏览器隐私模式会抛,忽略是对的
- `which cmd` 探测命令在不在 —— 抛了就是「不在」,返回 false 是对的

**真正要改的是这一类**:「目标必须存在 / 这一步必须发生」的地方。判别问一句 ——
**吞掉之后,页面/接口会不会看起来一切正常?** 会,就是必须改。
`platform-ops.mjs` 那两处正是:查不到列、算不出灯,页面照样渲染,空白格看不出是失败。

## 下批要做的

1. 逐处打标:合理(留) / 必改(目标必须存在) / 存疑(要看调用方)
2. 必改的那些:要么显式判断并报错,要么在断言里守住「它真的发生了」
3. 常驻扫描:新增的 `catch { return null }` 必须在提交时说明属于哪一类

# 附表 · `.hidden` 被覆盖(店主 09-24 立,同属「一类病不是一处」)

## 判据

**所有带 `hidden` 类的元素,渲染后的 `display` 必须是 `none`。不读 CSS,量 computed style。**
脚本:`tools/hidden-render-check.mjs`(导出 `SNIPPET`,浏览器里执行)。
判据自身先挨一刀:造一个 `class="hidden" style="display:flex"` 的元素,抓不到就报「判据自身失效」。

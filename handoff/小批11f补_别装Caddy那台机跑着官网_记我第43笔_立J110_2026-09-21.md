## 一 🔴🔴 **别装 Caddy。那台机器上正跑着有迹官网。**

交接文档(2026-09-18)写得清清楚楚:

```
生产地址   https://www.jingshengyouji.com
nginx      1.24.0 (Ubuntu) · 已 enable + active(开机自启)
站点根     /var/www/jingshengyouji/
配置       /etc/nginx/sites-available/jingshengyouji.conf
证书       Let's Encrypt · jingshengyouji.com + www · certbot.timer 自动续期
           🔴 到期 2026-12-17 · 注册时没绑邮箱 ⇒ 到期不会有邮件提醒
防火墙     22 / 80 / 443 全放行(443 是 09-18 补加的)
DNS        @ → 82.157.154.185 · www → 82.157.154.185   (🔴 api 这一条还没有)
登录       ssh -i ~/.ssh/youji_tencent_ed25519 ubuntu@82.157.154.185 · 免密 sudo
```

> **⇒ 11f §二 那条「装 Caddy」作废。Caddy 会来抢 80/443,把官网顶下线。**

### 改成:在现有 nginx 里加一个 server block

1. **新增一份** `/etc/nginx/sites-available/api.jingshengyouji.conf`(**不许改官网那一份**),`server_name api.jingshengyouji.com`,反代到 Railway 后端
2. **证书用 certbot 扩到子域**:`sudo certbot --nginx -d api.jingshengyouji.com`
   —— **自动续期已经在跑,不用另起一套**
3. **只转必要路径**,配 `proxy_set_header Host / X-Forwarded-For / X-Forwarded-Proto`、超时、访问日志单独一份
4. 🔴 **每一步之前先 `nginx -t`,之后 `systemctl reload nginx`(不是 restart)**
5. 🔴 **做完第一件事:确认 `https://www.jingshengyouji.com` 还活着。**
   **官网掉线一秒都不行 —— 它是备案要求「网站可访问」的那个网站。**

## 三 SSH:你有钥匙,不用走网页终端

`~/.ssh/youji_tencent_ed25519`(她本机,无密码短语),用户 `ubuntu`,免密 sudo。

## 四 🔴 一件我从交接文档里读出来的真风险(店主不知道)


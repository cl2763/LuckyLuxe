## 一、四件按裁定做的

### ① 十二条触发器统一(唯一出口)
新模块 `apps/api/ledger-guards.mjs`:七条禁删 + 五条禁改,全部由 `installLedgerGuards()` 一次装配。
`local-server.mjs` 里散在两处的定义清零(㋛① 常驻断言扫这件事)。
**没有用「先 DROP、删完再建回来」那套** —— 装配是启动期一次性完成,跑完这一句法就在,
不存在"法不在"的窗口给业务代码用。

### ② 判据从名字改成数据
`tenants.kind ∈ real | demo | test`(ALTER ADD COLUMN,默认 `real`),
豁免谓词只在 `guardedTenant()` 写一次:

```
COALESCE((SELECT kind FROM tenants WHERE id = OLD.tenant_id), 'real') = 'real'
```

**fail-closed**:tenants 里查不到这个 id(脏数据/建店半路失败)一律按 real 算 ——
宁可拦住一次合法清理,不许放过一次真账本的删除。

**根治那一层**:新建租户在**建店那一刻**就落 kind(测试库上建的 = test),
判据用的是「这台服务往哪个库写」(与测试护栏同一个 `DATA_SCOPE`)。
以后新残留自带标签,一句 SQL 筛干净 —— 不再需要谁去认前缀。

### ③ 清理脚本改判据
目标 = `SELECT id FROM tenants WHERE kind='test'`;前缀表 SUITE_PREFIX **整张退役**。
脚本新增「归属自证」一行:real/demo/test/无归属 各几个 —— 有无归属的行当场报出来,不许闷头往下删。

### ④ 护栏② 变成活的
店主指出原来那句「命中即抛错」是**装饰性断言**(targets 早把 PROTECTED 过滤了,永远不触发)。
现在断言落在**真正传进 DELETE 的参数数组**上(`assertNoProtected(pickTargets(db))`),
并且有两条**会红的测试**:
- ㋛⑥ 故意塞 `lucky-luxe` 进参数 → 必须抛错(实测抛了)
- ㋛⑦ 只塞测试租户 → 必须放行(不误伤)

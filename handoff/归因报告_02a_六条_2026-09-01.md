### 归因2 · 假图来源 —— **一行代码,已定位**

`miniprogram/utils/api.js:70-72`:
```js
function normalizeImage(url) {
  if (!url) return '/assets/images/store-cover.jpg'   // ← 就是这一行
  ...
}
```
**没图 → 直接回落成店铺环境照 `store-cover.jpg`。** 服务卡 `image: normalizeImage(service.imageUrl)`(:275)。

**为什么两端不一样**:网页端走 `apps/web/img-placeholder.js` → 出「还没有图片」占位;
小程序端走 `normalizeImage` → 出环境照。**同一份数据、两端两套实现,一端说真话一端编。**

**违反三条**(你点的三条全中):
- **占位零回落律**:`/assets/…` 按律等于"没人上传过",必须出占位 —— 这里反而拿它当兜底
- **编造律/假数回落红线**:顾客看到的图与事实不符
- **一份数据两端渲染律**:两端对同一事实给出不同答案

**同类扫尽范围(动刀时要一起清)**:`localImageMap` 那张表(:47-63)把一批 `/assets/*.png` 映射到 `.jpg`,
同属"平台自带资产当内容图"一族,需按占位律逐个判是"界面资产"还是"内容图位"。

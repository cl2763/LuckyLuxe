## 判据:两刀都咬到了,但第一刀是**先咬到我自己的判据**

常驻套件 24 条(两店各跑 + 越权 + 幂等 + 异常输入 + 未登录)。造病两刀:

| 刀 | 砍哪 | 咬住的 |
|---|---|---|
| ㋐ 反例集不按租户取 | 回流跨了店 | `③ 前置:那句话进了待审` |
| ㋑ 待审两层隔离一起拆 | SQL + 全录读口都不按租户 | `⑤ B 店待审里每一条都属于 B 店` |

**㋑ 头两轮没红,查清楚是两件不同的事:**
1. **头一版判据是黑名单式** —— 写的是「A 店那句话**不在** B 店列表里」。
   而列表有 200 条上限,CI 库里几百个会话一挤,A 店的轮次根本翻不到第一页,刀砍下去毫无反应。
   改成**白名单式**:「每一条都必须属于本店」,漏一条就红,与条数无关。
   (白名单判据 > 黑名单判据 —— 这条律今晚第二次救场。)
2. **隔离其实是两层守的**:我这条 SQL 一层,`readWecomTranscript` 自己按租户读又一层。
   只砍一层不漏 —— 这**不是判据废,是防线还在**。要证判据真在守,刀必须把有效边界整个切开。
   **「刀没红」有三种可能:判据废 / 刀砍空 / 防线真的还在**,三者从现象上分不出来,必须逐个排掉。

**顺手咬出我自己护栏的一个缺陷**:重启守卫用 `ps -o lstart=` 比启动时刻,
而它**只精确到秒** —— 重启够快时前后一模一样,守卫把好好的一刀误报成「验的是旧构建」。
改成比 **PID**。两把刀的脚本都已改(J-04 那条护栏的修补)。

## corner case 覆盖

| 类 | 覆盖 |
|---|---|
| 边界值 | 分母为 0 的认可率(给 null 不给 0);confidence 缺失显示「—」 |
| 空态 | 没有待审时的话术;新店一条都没审过 |
| 越权 | B 店裁 A 店的轮次 → 404;未登录 → 401;跨店回流两刀 |
| 幂等 | 同一轮裁两次 = 覆盖不追加(已裁决数不变) |
| 异常输入 | 「改一句」不给话 → 400;非法 verdict → 400;悬空轮次 → 404 |
| 并发时序 | ⬜ **没做** —— 两个人同时裁同一轮,靠唯一索引兜底,但没写断言 |

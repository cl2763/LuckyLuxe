多项目预约与串联结算

流程图 · 2026-09-03 · 图=合同 · 对应诉求总账「多项目预约 → 多单串联结算 → 合并推送」(08-11 店主设计)· 以 02b① 现查为底:项号级分账已在用,本图只补三处缺口

先把 08-11 的设计对到现状上:你当时说「一次约多个项目自动拆成 N 张单,逐张签名,合并页显示 N 单合计」。那是在一张单只能一项的年代。现在一张单已经能装 N 项、每项各自挂技师各自分成(02b 现查:284/386 行真在用)——所以「一次到店 = 一张单多项」是主路,不再为多项目拆单;拆成多张单只在不同时间结时发生(先做完的先结),那时它们成为一个「到店组」,合并推送一份「N 单合计」。逐张签名照旧:每张单在它结算那一刻签,组不共用签名。要补的只有三处:卡耗按项、小记按项号、到店组合并推送。

一、主路:一次到店,一张单,N 项

1 预约
一张预约,N 个项目
顾客端/台面一次选多项;每项可指定技师或留空;总时长 = 各项相加(现有)
2 到店
台面一格,内含 N 项
在做/完成按单;到店人次按单去重(与大屏口径一致)
3 开单
一张结算单,N 行项
每行:项目 · 技师 · 价档 · 金额(现有 settlement_items + item_nos_json)
4 付法
每一项各自选付法
现付 / 储值 / 次卡第 n 次;单头合计由各项汇总,不再只在单头记一次卡耗
5 签名
一次签,覆盖整单 N 项
现有电子签;签名图挂单(D107 已回订单详情)
6 小记
小记挂到「这一单第几项」
键 = 单号 + 项号(+技师);项目名只是快照,改名不丢
7 推送
一份电子票据,N 项明细
现有票据;每项显示付法(现付 / 储值扣 ¥ / 次卡第 n 次)
① 法式加钻 · 小雅CAD 168 储值扣 168
② 睫毛嫁接 · 苏苏CAD 120 次卡 第 3/10 次
③ 卸甲(加项)· 小雅CAD 20 现付
合计CAD 308 · 实付 20

二、支路:先做完的先结 → 到店组

A
同一次到店,分开结
例:美甲先做完先结,睫毛一小时后再结——两张单,各自签各自推
B 成组
自动归入同一「到店组」
规则:同顾客 · 同店 · 同一营业日 · 前一张单结算后 4 小时内;现有 group_id 复用;人工可拆/可并(留痕)
C 合并推送
一条「本次到店 N 单合计」
组内最后一张单签完后推一条汇总:N 单 · 合计 · 各单入口;每张单自己的票据照发
D 顾客端
「本次到店」合并页
顾客端订单列表按到店组折叠:一行显示 N 单合计,展开看各单;单张单仍可单独打开、单独售后

为什么不共用签名:每张单在结算那一刻各自签,是店主 08-11 的原话,也是现状;组只负责「看起来是一次到店」,不负责法律上的一次签署。这样一张单的售后、冲销、分账都不受组影响。

三、三处缺口的落法

缺口现状(02b 现查)落法判据
① 卡耗按项卡耗只在单头(timecard_id/timecard_nth、储值扣减挂单),带卡的 12 张单全是多项单——分不清哪一项花了卡settlement_items 加 pay_source(cash / stored_value / timecard)、timecard_id、timecard_nth、stored_value_cents;单头字段改为各项汇总(条件迁移:存量单头值下放到第一项,标 migrated_from_header=1);大屏「总卡耗」与技师业绩从项级取数任一多项单:Σ 项级储值扣 = 单头储值扣;次卡第 n 次只在一项上;造病(两项都标同一张次卡同一 nth)必红
② 小记按项号service_notes 按 booking_id + technician_id + service_name 挂,项目改名或同单两项同名就串加 settlement_id + item_no,service_name 降为快照;写小记入口从「这一单的第 n 项」进;存量条件迁移:能唯一对上项号的补上,对不上的留空并标 item_no=null(不猜)同单两项同名各写一条小记,读回各归各;改项目名后旧小记仍在原项下
③ 到店组合并推送9 个多单组存在,签署按单号逐单,组零连带,无合并推送成组规则见 §二 B;组内最后一张签完触发一条汇总推送(走通知调度器,事由 visit_summary,幂等键 = group_id);顾客端订单列表按组折叠造两张同顾客同日单 → 自动同组 → 第二张签完只推一条汇总;第三张 5 小时后结 → 新组;人工拆组留痕行存在

四、明确不做

不为多项目自动拆单;不做组级共用签名;不做跨店到店组;不做组级售后(售后仍按单)。

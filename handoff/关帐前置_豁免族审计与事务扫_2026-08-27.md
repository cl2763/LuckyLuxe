## 二、事务扫:五处 + 两处,通则成立

| 动作 | 几步写 | 在不在一个事务里 |
|---|---|---|
| 结算签署(收入入账 + 储值扣卡 + 次卡核销 + 定金兑现) | 多步 | ✅ `BEGIN IMMEDIATE … COMMIT/ROLLBACK` |
| 金额更正(留痕 + 账本差额 + 券退回 + 储值补配 + 次卡返还) | 多步 | ✅ 同上 |
| 日结确认(close 行 + 每技师快照行) | 多步 | ✅ 同上 |
| 冲销(手工红字) | **1 步** | ✅ 一步即原子 |
| 退储值(N-5) | **1 步**(单条 INSERT,拆账两列同行写) | ✅ 一步即原子 |
| **充值 + 赠送** | **2 步**(recharge 行 + bonus 行) | ❌ **裸的,没有事务** |
| **退次卡** | **2 步**(扣次数 + 写退款记录) | ❌ **裸的,没有事务** |

两处都已包进事务。坏的方向长这样:
- **充值+赠送**:第二行挂了 → 顾客钱收了、赠送没到账,**账面上看不出少了什么**;
- **退次卡**:第二步挂了 → **顾客的次数没了,系统里却查不到"退给过她钱"**,事后谁也说不清。

**通则成立,立律**(已入 `CLAUDE.md`《又三律》第六条):
> **凡动钱的多步写,要么压成一步,要么包在一个事务里,不许有第三种。**

判据两层:
1. **静态(白名单式,不列举被测对象)**:全仓扫 **707 个函数**,凡函数体里对钱表
   (`finance_transactions` / `stored_value_transactions` / `member_timecards` / `timecard_refunds` /
   `points_transactions` / `deposit_receipts`)有 **≥2 处写**,必须带 `BEGIN IMMEDIATE` —— **0 例外**。
2. **行为(注入一次失败)**:临时挂一条只拦 bonus 行的触发器 → 充值必然在第二步炸 →
   断言**第一行也不在了**;再加反向守:不注入失败时两行都落库
   (否则"根本写不进去"也能让上一条绿)。

**这条静态扫我做过突变自检**:把退次卡的事务去掉 → 扫描当场报出违规 1 处。不会红的判据不算判据。

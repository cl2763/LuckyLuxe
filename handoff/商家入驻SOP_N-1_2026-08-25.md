# 商家入驻 SOP(N-1)· 2026-08-25

给平台侧照着做的一份清单。顺序有讲究:**先配大类,再配项目** —— 反过来会卡住。

## 0. 建店(平台后台 → 商家管理 → 新建商家)

- 填:商家名称 / 城市 / 套餐 / 首期(年付·月付·试用30天)/ 租户 id(选填)
- 🔴 **「这是演示店」这个勾**:真商户**不要勾**。勾了 = 这家店的账本不受只追加律保护、可被一键重置,
  对外也不能拿它说"账本不可篡改"。勾选时系统会二次确认并写运维日志。
- 建完记下老板账号与初始密码(**只显示一次**),交给商家首登改密。

## 1. 🔴 大类:**配一次就够,不存在第二个地方**

【分类唯一真相律 · 店主 2026-08-25 立】

- 分类是**两级,不是两套**:
  - 上层 = **大类**(店内大类字典)。平台三类「美甲 / 美睫 / 护理·其他」是**默认起点** ——
    建店时系统已自动落好,不用手工加。
  - 下层 = **款式**,就是项目本身,挂在大类下,**不再自成一组**。
    (店主原话:「美甲这个大类下面直接挂着八个款式就可以」)
- 商家想细分就细分(小婕那家就细成六类:美甲单色 / 简单款式 / 复杂款式 / 美睫 / 护理 / 卸甲)。
  改大类的地方**只有一处**:平台后台 → 商家配置 → **大类字典**。
- 商家端是**只读**的(v1.4 口径):商家看得到分组,改不了字典。
- **一个项目的分类只有一处真相 = 挂在哪个大类下。**
  项目上那个自由文本「分类」框已经**取消**了 —— 以前它和大类各说各的,
  顾客端就会变成「8 个分组各 1 项」,等于没分组,而商家后台那边看着还是好的,所以一直没人发现。

## 2. 项目(价目表)

两条路,都受同一条律管:

**A. 一条条建**(平台后台 → 商家配置 → 服务价目)
- 每个项目**必须选一个大类**才能建/上架 —— 不选会被拒(`CATEGORY_REQUIRED`),不会悄悄留空。

**B. 批量导入**(推荐,店多的时候)
- 模板**必须有「大类」列**。列名认这些:大类 / 分类 / category。
- 其余列:项目名(必填)· 英文名 · 类型 · 价格(元,必填)· 定金 · 时长(分钟)· 排序
- 先**试跑**:报告会逐行告诉你**哪一行缺大类、哪一行的大类不在字典里**(带行号)。
- 🔴 **一行有问题就整批不进库** —— 要么整批干净进,要么一行不进。半批进库最难收拾。
- 大类名要与字典里**一模一样**(或用 key)。字典里没有的名字会被退回,不会自动新建 ——
  新大类请先在「大类字典」里加。

## 3. 其余配置(顺序随意)

门店信息 / 营业时间 / 技师 / AI 知识库(本店)/ 会员制度(平台定)/ 定金与取消规则。

## 4. 交付前自查

- [ ] 大类字典里的名字,是商家自己会说的话(不是我们替他起的)
- [ ] 每个上架项目都挂了大类 —— 商家后台「上架服务」页看不到「未归类」那一组
- [ ] 顾客端(小程序/网页)分组名 = 大类字典名
- [ ] 演示店的勾没有误勾到真商户身上

## 一、J-20 · 定金金额两处真相 → 合并(现修)

**现状(我读的)**:钱按 `tenant_settings.deposit_config` 算(`local-server.mjs:6609/6619/7681/10798` 全走 `depositAmountForService`);而知识库另有一个 `tenant_kb_facts.depositAmount`(种子 `:1208` 写 `'50'`;写口两处:`kb-routes.mjs:37` 与 `local-server.mjs:13664` 的 allowed 白名单;读口:`kb-utils.mjs:137` 进提示词、`ai-fact-gate.mjs:32` 进事实槽)。商家在知识库改成 60,AI 会说 60,顾客到店付的却是配置算出的 50——**这正是事实闸要防的「说的和收的不一样」**,只不过这次编数字的是我们自己的两张表。事实闸现在把两个数都当「槽内」放行,等于给漂移开了后门。

**裁**:`deposit_config` 唯一真相(账本红线:钱从哪算,话就从哪说)。知识库那个键**不再是可写事实**。

**修法(六件,同族一次改)**:
1. `kb-utils.mjs:137`:`depositAmount` 不再读 `live`/种子,改为**由本店 `deposit_config` 派生**(fixed → 固定额;per_service → 兜底额,并在提示词里注明「按项目不同,以预约页为准」);`tenantKbFacts` 仍是唯一出口,只是这一项的来源换成配置;
2. 两处 allowed 白名单**去掉 `depositAmount`**;再传它 → `400 UNKNOWN_KB_KEY`(D134 同一口径,不新造错误码),响应 hint 写明「定金金额请到 门店设置 → 定金规则 改」;
3. 种子 `:1208` 那行删掉;
4. `ai-fact-gate.mjs:32` 那行删掉——槽③只认 `deposit`;
5. **库里已有的 `depositAmount` 行不删**(本机库现值 50,与配置等价;删行是 4128 写,不值得为它走沙箱预演 + 批)。读口全部断开后它就是死数据,写进两库对照表「废弃键」一栏,上线批清;
6. 撞红的老断言 `tenant-kb`「AI 定金答案用更新后的事实(60)」**改造景**:改 `deposit_config` 兜底额 → AI 说新数 → 事实闸放行;把知识库 `depositAmount` 改 60 → 400。

**判据**:
- 静态:仓内 `depositAmount` 出现处白名单式列举——只许在 `depositAmountForService` 族、前端显示、和这条判据本身;写白名单 0 处、种子 0 处、事实槽 0 处;
- 行为:改配置 → AI 答新数且不被拦;`PUT` 知识库 `depositAmount` → 400;两店各跑一遍(小婕镜像为主);
- 造病:把 `depositAmount` 加回任一 allowed → 静态红;把 `ai-fact-gate.mjs:32` 那行加回 → 行为红(知识库 60 与配置 50 并存时,「60」不得放行)。

**同族扫(点名处必扫同族律)**:allowed 白名单里其余五个键(`brandName / assistantName / storeAddress / storePhone / currency`)逐个报:**这个事实在仓里还有没有第二处真相**(例:`storeAddress` vs `PUT /platform/tenants/:id/store {address}`;`currency` vs 租户币种)。**只报不修**——列表交回,我入总表(D139 族)排到 ④/⑤ 或 S5;凡是钱相关(`currency`)的注明。

# 判据缺陷 · J 族 · 「静默返回白名单」判据自身三修(2026-09-04,大批05 ①)

> 立册依据:《突变自检条》——「**判据也是代码,也会坏,也该有缺陷号。**」
> 这三条不是产品缺陷,是**判据缺陷**。三条里有两条是我自己写的判据在自证时露的馅,
> 第三条是**造病验红当场咬出来的** —— 没有那一刀,它会以「11 项全绿」的样子交出去。

## 背景:这把判据在守什么

D133 的根:一轮没命中关键词 → 会话进 `needs_human` → **AI 从此不说话**。
图 v1.1 §一裁:只有**人工真正接管**(`human_active`)才静默,`needs_human` 只是「已转给同事」。
所以要一条常驻判据守住:**全仓每一处「静默返回」都必须有正当理由**。

## J-01 分母错:拿 `waitingForHuman: true` 当「静默」

第一版扫 `waitingForHuman: true`,全文件 4 处。但其中 **2 处是带回复的**
(行 3715 报价等待、行 3890 报价单已推送),它们 `waitingForHuman` 为真只是「在等人工」,
**不是静默**。用错的分母判对错,结论必然是错的。

- **改法**:收窄到真正的静默形状 `reply: null, waitingForHuman: true`(2 处)。
- **归族**:判据不许锚在「看起来像」的字段上 —— 要锚在**被守的那个事实**上。

## J-02 魔法窗口:「往前 1500 字符找守卫」

第二版按固定字符窗口回溯找守卫。`silentHandoffUnknown` 里那处离它的函数头 **55 行**,
窗口够不着 → **守卫明明在、判据说不在**(假红)。

- **改法**:不设窗口,按语法结构定位。
- **归族**:判据里出现魔法数字(1500 / 20 行 / 前后各若干)就是雷 —— 代码一长一短它就翻脸。

## J-03 🔴 作用域取粗一格 → 白名单退化(**造病验红当场咬出**)

第三版改成「按**所在函数**找守卫」,`test-ai-gate` 11 项全绿。
然后按《突变自检条》造病:往 `needs_human` 分支里新塞一处静默返回
(真会发生的写法 —— 「顺手也让它别答了」),**重启服务**后重跑:

```
✅ test-ai-gate 通过 11 项      ← 病在,判据照样绿
```

**根因**:`handleWecomInbound` 是个几百行的大函数,函数体里**更早**那个合法的
`if (existing.status === 'human_active')` 守卫,把后面新塞的违规**洗白了**。
作用域取粗一格,白名单就退化成「这个函数里有过守卫就算数」—— 等于没守。

- **改法**:按**所在代码块**定位 —— 从静默点往上做花括号配平,找到直接包着它的那个 `if`,
  守卫必须写在**那一个** `if` 上。
- **落刀四步(全做)**:
  | 步 | 结果 |
  |---|---|
  | ① 造病(语义变异,`node --check` 仍通过) | ✅ |
  | ② **重启服务**(4399) | ✅ |
  | ③ 跑 → **必须红且报得出哪一处** | ✅ 红,报出「无家可归 1 处:行 3789」 |
  | ④ 还原 + 重启 + 重跑 → **必须回绿** | ✅ 11 项通过 |
- **归因**(证明新层真在守,不是数量凑巧):同一份「病」数据喂**上一版**判据(按所在函数)
  → **绿**;喂这一版(按所在块)→ **红**。同一把刀分得出哪层在守。

## 留下的护栏

1. 判据里**不许再用字符窗口**找语法上下文;要么按块配平,要么按 AST。
2. 巨型文件里的白名单判据,**作用域一律取到最内层块** —— 函数级在 18,000 行的文件里等于没有。
3. 本条判据的报错信息带**行号**(`无家可归 1 处:行 3789`),否则红了也不知道红在哪(刀留痕律)。

## J-04 🔴 **验证环境本身是假的** —— `pkill -f "PORT=4399"` 一次都没匹配上

写完 J-03 之后又查出一件更根本的:我用来重启探针服务的命令是

```
pkill -f "PORT=4399"
```

**`PORT=4399` 是环境变量赋值,不在进程命令行里**(命令行只有 `node local-server.mjs`),
所以这条 pkill **一次都没匹配上**。后果是:第一次起的那个进程(`00:00:16`)一直在服务,
之后每一次「重启」都是新进程撞 `EADDRINUSE` 悄悄死掉,**旧进程继续应答**。

于是 **00:00 到 00:41 之间,所有打在 4399 上的行为断言,验的都是 40 分钟前的构建**。
CLAUDE.md 里早写过同一个坑的另一面(「macOS 拿不到别的进程的环境变量,4310 的 DATA_DIR 探不到」),
我在 4399 上又踩了一遍。

**受影响的结论,逐条重做**:

| 当时的结论 | 真相 | 重做后 |
|---|---|---|
| 「⓪b 脱敏正门搬迁后端到端通过」 | 验的是**搬迁前**的内联路由 | 已按 PID 重启后重验:`400 REASON_REQUIRED` / `200 行数 5→5` / 留痕齐 ✅ |
| 「两套件改成新口径后通过」 | 服务是旧档,新口径**恰好也绿** | 真重启后**当场红** —— 说明默认档确实是旧门,判据在守 |
| 「造病:11 项全绿(J-03 露馅)」 | ③ 真的坏(静态判据,与服务无关);**② 是被旧服务盖住的** | 见下 |

**J-03 的归因要拆成两条,不许合并成一个更好听的故事**:
- ③(静态,读源码)**确实被函数级作用域洗白了** —— 它不碰服务,这条结论不受 J-04 影响,成立。
- ②(行为,D133 反面)当时绿,**不是判据不行,是它问的那台服务器根本没装上病**。

现在 `test-ai-gate` **自带实例**(每跑新建 `ll-ci-data.aigate*` 临时库 + 独立端口 + `AI_GATE=model`),
不再依赖任何外部服务;重做造病,**②③ 两层同时红**:

```
not ok 3 - ② 🔴 D133 反面:范围外一句之后,同一会话下一句「营业时间?」必须得到回复
not ok 4 - ③ 🔴 白名单:每一处静默返回都必须落进…两类之一
```
还原后 `✅ test-ai-gate 通过 11 项`。

**永久护栏(三条)**:
1. **不许再用 `pkill -f "PORT=xxxx"` 关服务** —— 端口不在命令行里。
   一律 `lsof -nP -iTCP:<port> -sTCP:LISTEN` 取 PID 再 kill,并**回读确认端口真的空了**才起新的。
2. **重启后必须验「新进程起于什么时候」**(`ps -o lstart=`),对不上批次时间就是没重启成。
3. **行为断言不许依赖「我以为我重启过」的共享服务** —— 需要特定配置的套件自带实例
   (`test-ai-gate` 已改;`test-schema-consistency` / `test-perf-base-migration` 本来就是这么做的)。
   顺带堵掉的假绿面:端口若已被占,套件**拒跑并报错**,不再默默连上别人的服务。

**归族**:这是《突变自检条》第②步「重启服务(不是热改了事)」的失败案例 ——
**规矩我知道、命令我写了、它没生效,而我没验它有没有生效**。
判据律的推论在这里同样成立:**「我执行了某个动作」本身也需要判据。**

## J-05 判据「看形态不看效果」——`import` 了就算接了护栏

`test-db-target-guard` 的 ①c 扫「A 类脚本有没有接 `requireTarget`」。
我给 `tools/ai-eval/run-edge-80.mjs` 加了 `import { requireTarget } from '../db-target.mjs'`

同族:《判据律》「能验渲染结果的就别验中间产物」、08-23 那次「验 alpha 通道而不是验像素」。

**当批已改**:调用真接上,并现测「不给 `GATE_DB` → 礼貌拒跑」。
**扫描器本身的加固登记待排**(不在本批范围):
`requireTarget` 应当验到「**被调用且其返回值就是传给 `DatabaseSync` 的那个值**」,
而不是验它出现过。判据四说得清楚:同一把刀要能分出哪层在守 ——
现在这一层守的是「作者记得写 import」,不是「护栏真的拦得住」。

# 已报价状态机 · 实施小方案(31l 二;**先方案后动工,核过再建**)

依《商家回访11项需求_完整方案》#11(P4.1)与《有迹待办总方案》§6;现有字段现测对齐。

## 1 「本次会话」的定义

同一顾客,距**上一条往来消息**(无论谁发)超过 N 小时无往来 → 下一条消息开启**新会话**。
- N 默认 **6 小时**,每店可配(`tenant_settings key='session_gap_hours'`,后端闸 1~72);
- 落库:`wechat_conversations` 增列 `current_session_id TEXT` + `session_started_at TEXT`
  (try/catch ALTER;消息入口处判定与翻转 —— 入口只有一个:进线消息写入函数,不散点);
- 会话切换**不删任何记忆**(方案原文:完整聊天记录/AI 工作记忆/顾客画像全挂顾客维度,只翻 session 标)。

## 2 报价有效期

- `quote_requests.expires_at` 已有 —— 补规则:**报价生成/mark-quoted 时** `expires_at = now + quote_valid_hours`;
- `quote_valid_hours` 默认 **48**,每店可配(同上 tenant_settings,闸 1~336);
- 过期不改行、不删行:读时算 `expired = expires_at < now`(零态翻转靠读,不靠定时器)。

## 3 状态机(状态 × 迁移 × 触发)

会话报价态 = f(quote_requests × current_session_id × expires_at),**读态推导,不另存状态列**(一个事实一处真相):

| 态 | 判定 | 工作台横幅 |
|---|---|---|
| A 本次已报价 | 本会话内存在 quote(mark-quoted 落的),未过期 | 「本次会话已报价 ¥X · 技师 · N 小时前 · 有效期至 …」 |
| B 已报价·已过期 | 本会话内 quote 已过期 | 「本次会话已报价(已过期)¥X — 需重新确认」 |
| C 历史报价参考 | 本会话无 quote,但该顾客历史会话有 | 「历史报价参考:上次(N 天前)报过 ¥X · 技师 — 本次尚未报价」 |
| D 未报价 | 都没有 | 无横幅 |

迁移触发:进线消息(可能翻新会话:A/B→C)· mark-quoted(→A)· 时间流逝(A→B,读时判)。

## 4 醒目标记形(客服工作台)

- 网页客服台会话头部横幅三态三色(A=实色 / B=警色 + 「重新确认」按钮 / C=灰底参考句),句**后端出**
  (新读口 `GET /admin/conversations/:id/quote-state` 或并入现有会话详情响应 —— 倾向后者,零新路由);
- **改价硬防线**(方案原文):同会话已有有效报价,另一技师 mark-quoted 不同价 → 需 `confirmOverride: true`
  重发,且写 `quote_price_changes` 留痕表(id/conversation/old/new/actor/时刻);
- AI 侧:human-handoff 链路把 quote-state 并进上下文;过期后 AI 改口「上次报价已过期,我帮您重新确认」
  (话术进 kb,受 matrix 66 保护面外的新增句,单独断言)。

## 5 与 quote_requests 现有字段映射(现测)

| 现有 | 用法 | 需动 |
|---|---|---|
| `quote_requests.expires_at` | 已存在 | 只补写入规则(§2) |
| `quote_requests.status`(CLOSED 等) | 既有生命周期 | 不动;报价态是叠加视图 |

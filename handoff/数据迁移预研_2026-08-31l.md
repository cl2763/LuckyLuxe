# 旧软件数据迁移 · 预研报告(31l 四;只查不建,方案你与店主定)

## ① 主流美业 SaaS 有没有会员/余额导出?

店主与小婕现用的两家**名字待店主提供**(拿到名字我再逐家现查后台文档)。先按国内美业 SaaS 通行情况预答:
- 多数商家后台有「会员列表导出 Excel/CSV」(名/手机号/余额/次卡余次/累计消费,常见于会员管理页右上);
- 部分把导出锁在**高级版/连锁版**,或只给「报表页」(可打印不可下载)—— 报表页也能用:整页另存/截图 → 人工转表;
- 极少数彻底无导出:走③运营式迁移。

## ② 若有导出:P6 导入工具吃 Excel 的字段映射草案

现有地基:平台侧 `POST /platform/tenants/:id/import/customers`(dryRun 预览/幂等/is_migrated 标 +
legacy 余额桶 legacy_total_spend_cents —— membership 套件已断言「迁移客算会员/legacy 桶分开」)。

| 模板列(中文表头) | 落点 | 规则 |
|---|---|---|
| 姓名* | users.display_name | 必填 |
| 手机号 | users.phone | 去重键之一;空=允许(轻档案) |
| 储值余额(元) | 期初储值行(type=migration,legacy 桶) | 分币化;0/空=不建行 |
| 次卡名 / 剩余次数 / 到期日 | member_timecards(card_source='migrated') | 三列一组,可多组 |
| 累计消费(元) | legacy_total_spend_cents | 只作会员判定与画像参考,不进本店账本 |
| 生日 / 备注 / 标签 | users 对应列 | 选填 |

口径红线:期初余额**不写账本收入行**(不是本店赚的钱);dryRun 全量预览+差异表;重跑幂等一分不动。

## ③ 若连导出都没有:运营式迁移路径

顾客扫码自建档(绑定微信)→ 首访自报余额 → 店主对旧系统截图核对 → **账户调整·充值口**录期初
(payChannel=migration 类,note 写「旧系统迁移·核对人」)。
**风险与对策**:
- **报多**(顾客虚报):核对以旧系统截图为准,店主当场核;差额>阈值(如 ¥200)记「待复核」标签不即时入账;
- **报少/漏报**:迁移期(建议 4 周)内随时可补录,补录同一口留痕;
- **纠纷话术**(给店员):「余额以老系统记录为准,我拍个屏跟您核一下 —— 多退少补,迁完以后小程序里随时看得到,不会再糊涂」;
- 迁移期结束出**对账单**:期初合计 vs 旧系统导出/截图合计,差异逐人列。

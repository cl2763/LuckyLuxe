# 租户回落裁定 · 落地件(店主 2026-08-23 拍:案①改良版)

> 同族第四例、也是最深一例:**拿不到真值就回落到别人家的店** —— 小婕的顾客会看到 Lucky Luxe 的服务与加币价。

## 一、③ 先查明:所有依赖该默认的进入路径(改前逐条确认不会白屏)

| # | 进入路径 | 改前行为 | 改后行为 | 白屏风险 |
|---|---|---|---|---|
| 1 | 小程序**冷启动**(无 query、无记忆) | `|| 'lucky-luxe'` → 静默进旗舰店 | 首页守卫已在 → **进选店页**(3 家店可选,实测) | 无(选店页只依赖平台级 `/shops`) |
| 2 | 小程序**扫店内码 / 深链**(`?tenantId=` / `?merchant=` / `scene=t=`) | 写入记忆,正常 | **不变**(有真值) | 无 |
| 3 | 小程序**深链直达非首页**(分享出去的服务详情等) | 首页守卫管不着 → 静默用旗舰店取数 | **request 层守卫**:无租户不发请求 → 送去选店页 | 无 |
| 4 | 小程序**选店页 pick** | 写入记忆 | 不变 | 无 |
| 5 | 小程序**已进过店**(有记忆) | 记忆优先 | 不变 | 无 |
| 6 | 网页**专属链接** `?store=` | 写 localStorage | 不变 | 无 |
| 7 | 网页**无参、有记忆** | 记忆优先 | 不变 | 无 |
| 8 | 网页**无参、无记忆**(直接打开域名) | `|| 'lucky-luxe'` → 静默进旗舰店 | **「请选择门店」引导屏 + 自动弹选店面板** | 无(引导屏是实体内容,不是白屏) |
| 9 | 网页**选店面板被关掉** | — | 页面停在引导屏;下一次请求再弹 | 无 |
| 10 | **商家端**(小程序 merchant-*) | 走 `adminRequest`,租户来自登录会话 | **不受影响**(不读 `lucky_tenant`) | 无 |
| 11 | 后端 `validTenantId` 空值 → `DEFAULT_TENANT_ID` | 服务端兜底 | **保持不动**(平台/商家侧需要);顾客端已在前端拦住,不再依赖它 | — |

## 二、①②⑤ 落法

1. **租户唯一出口**:`api.currentTenant()` = 记忆(`lucky_tenant`)→ 部署配置 `deploy.defaultTenantId` → **空**。
   新增 `api.hasTenant()` / `api.currentTenantId()`,页面不再各自 `getStorageSync(...) || 'lucky-luxe'`。
2. **部署配置项**(不硬编码店名):`miniprogram/utils/deploy.js` 与 `apps/web/deploy-config.js`,均 `defaultTenantId: ''`。
   单店部署改这一个地方;多租户构建保持空 = **结构性禁止回落**。
3. **守卫**(双端同刀):无租户时**一个数据请求都不发** —— 小程序 `reLaunch` 到既有 `pages/shop-select`;网页弹既有 `openStoreSwitcher()` 并渲染「请选择门店」引导屏。`/shops`(平台级)放行,否则选店页自己也拿不到数据。
4. **顺带清掉的同族硬编码**:`home` 店名回落 `'Lucky Luxe'`、`me` 快照租户戳(两行重复也一并清)、网页 `storeId = 'store-ontario-01'`。

## 三、④ 断言(㋒ 组 6 条,常驻)

①顾客端全仓零硬编码租户名(剥注释后 0 残留)②默认店只能来自部署配置项且多租户构建为空 ③`currentTenant` 三段式无兜底 ④双端守卫在场且 `/shops` 放行 ⑤网页无租户=引导屏非白屏 ⑥网页门店 id 不再写死旗舰店。

## 四、假设(图上没画到)

- 网页引导屏文案:「请打开店家给你的专属链接、扫店内小程序码,或在下面选择门店。」
- 顾客关掉选店面板 → 停在引导屏(不自动重弹,下一次数据请求才再弹),避免关不掉的死循环。

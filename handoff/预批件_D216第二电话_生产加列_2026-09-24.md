## 一、要做什么

`stores` 表加一列 `phone2 TEXT`(第二联系电话,可空)。

## 二、写死的 SQL(执行时逐字照跑,不即兴改)

```sql
-- ① 执行前留痕
SELECT COUNT(*) AS stores_before FROM stores;
SELECT COUNT(*) AS has_phone2_before FROM pragma_table_info('stores') WHERE name='phone2';

-- ② 加列(幂等:已存在会报 duplicate column,按「已加过」处理,不算失败)
ALTER TABLE stores ADD COLUMN phone2 TEXT;

-- ③ 执行后核对
SELECT COUNT(*) AS stores_after FROM stores;
SELECT COUNT(*) AS has_phone2_after FROM pragma_table_info('stores') WHERE name='phone2';
SELECT COUNT(*) AS phone2_nonnull FROM stores WHERE phone2 IS NOT NULL;
```

## 三、前后 COUNT(预期值)

| 项 | 执行前 | 执行后(预期) |
|---|---|---|
| `stores` 行数 | **N**(执行时现测并记录) | **N,一行不增不减** |
| `pragma_table_info` 里有 `phone2` | 0 | **1** |
| `phone2 IS NOT NULL` 的行 | —— | **0**(加列不填值) |

🔴 **`stores` 行数前后必须完全相等**。不等就是出了别的事,立即停并回报。

## 四、备份

执行前必须先手动备份生产库一次,**路径写进回报**:
```
railway ssh 进容器 → sqlite3 /app/apps/api/local-data/lucky-luxe.sqlite ".backup '/app/apps/api/local-data/backups/pre-phone2-<时间戳>.sqlite'"
```
备份文件大小与时间戳都要回报;**备份没做成就不执行 ALTER**。

## 五、回滚

SQLite 支持 `DROP COLUMN`(3.35+):
```sql
ALTER TABLE stores DROP COLUMN phone2;
```
⚠️ 执行前先现测生产的 SQLite 版本:`SELECT sqlite_version();`
**低于 3.35 则没有 DROP COLUMN**,回滚只能靠 §四 那份备份恢复 —— 这种情况下备份就是唯一回滚路径,必须确认备份可读。

## 七、风险

- 加列本身对现有行为**零影响**(新列全 NULL,读的地方都还没有)

  所以 §六 最后那条(重扫出口普查表)必须同批做完,不许拆开

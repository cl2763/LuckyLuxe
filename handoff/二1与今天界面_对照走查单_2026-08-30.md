## 一、二.1 小程序账户调整(充值/赠送/退卡/冲销)

**在哪**:商家小程序 → 客户档案 → 点开某位顾客 → **「账户调整(充值 / 赠送 / 退卡 / 冲销)」**按钮
(写服务小记/顾客画像那两颗下面)。店员账号**连客户档案页都进不来**(guardOwner),接口层再兜 403。

**与网页同一个后端出口(零第二实现)**:

| 块 | 同一条口 |
|---|---|
| 四个参考数(实付/赠送/已消费/余额)+ 界限句 + 提示 | `GET /admin/account-adjust/facts`(句子全部后端给) |
| 黄条「你正在退出赠送部分」 | 同上带 `amountCents`(后端句,前端不自己算) |
| 退储值(硬拦超余额/原因必填/幂等 requestId/拆账两腿) | `POST /admin/stored-value/refund` |
| 退次卡(退完剩 0=卡作废) | `POST /admin/timecards/:id/refund` |
| 充值 / 赠送 / 冲销 | **指路**到各自正式入口(与网页同策略 —— 同一件事两处写口=迟早分叉) |
| 财务门禁 | 页面进门先查 `finance/lock-status`,没解锁指去财务页(D27 先例);接口层 `requireRefundRight` 最终闸 |

**判据 17 项全绿**(`test-mini-account-adjust.mjs`):源码层 8 条(每条口逐一钉)+ 行为层 7 条
(黄条句 / 超退拒 / 原因必填拒 / 合法退成功带拆账两腿 / **幂等重放不再扣**)+ 店员 403 两条。
**变异**:摘掉页面 guardOwner → 判据红 —— 第一刀**没红**(判据被头部注释里的字面量喂饱),
当场修成剥注释再扫,第二刀红。**突变自检又抓到一条判据自身的病,这就是它存在的意义。**

**像素欠着如实报**:本机没有微信开发者工具,小程序端证据=源码链+接口层;店主手机上照上面路径走即见。

## 一、五件裁

**(1)③ 并发没验 → 裁「草稿不占位,占位在落单」。**
草稿(`drafted`)是意向,不是占位;两个人同时确认同一时段,**允许两张草稿都建出来**。真正不许双占的是 `booked`(定金完成 → 落单)那一刻:落单必须在 `BEGIN IMMEDIATE` 事务里**同事务复查可约**,查到被占就落不下去,顾客拿到「这个时段刚被约走,换一个?」并回 `checking`。判据(③b):同槽两会话并发确认 → 两张草稿;随后并发落单(用现有落单口造景)→ **恰好一张成功**,另一张 409 + 回复文案;同会话复确认仍同一 draftId(④e 已有)。造病:去掉同事务复查 → 两张都落 → 红。

**(2)④ 像素层 → 店主亲眼看,Code 不截「自己摆的样子」是对的。**
店主:打开本机后台(4128)→ 用 `handoff/本地自查账号.txt` 里的老板账号登录 → 「AI 客服 → 待审」;看三件:列表有没有条目、点「对」三个数会不会动、点「改一句」空着能不能提交。看完一句话告诉我「像样 / 哪里不像样」,我记进回执,⬜ 才翻 ✅。密码不进任何文件与对话(四之十 6)。

**(3)「本周模型放行」其实是全部历史 → 接上时间窗,文案改「近 7 天」。**
前端传 `since=7d`;三个数都按窗算(放行 / 认可率 / 反问率);判据:造一条 8 天前的放行(造态要造在判据真正读的那一列 `created_at`)→ 不计入;7 天内 → 计入;造病:去掉窗 → 红。

**(4)动了既有判据 `test-ai-gate ①d`(字面量锚 → 守语义、更严、造病验红后还原)→ 收,登记 J-24。** 以后动既有判据照这次的做法:回执单列「动了哪条、为什么、造病验红的原文」。

**(5)`MP_AUTOMATOR` 检测不到 → 红。** 「没跑也算过」是零断言那一族。裁:默认红;只有显式 `MP_AUTOMATOR=skip` 才不红,且**计进「本轮未跑」**并在回执写原因——不许绿。

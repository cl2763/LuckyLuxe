# D68 · L2 文案扫尽清单:用户可见处的「组/张」内部话术(2026-08-23)

> 口径(店主 08-23 原话):层级=**大类 → 项目 → 加项**;**N 数的是「项目」(主项目)**——
> 加项不计、自选填写行不计、现场购卡不计、大类不是计数单位。
> 当前模型每张单恰一主项目,故数值上=张数;**实现与断言一律以「主项目计数」为锚点**(后端唯一出口 `groupMainItemCount`)。

| # | 位面 | 现文 | 为什么留 |

| a | 商家日结「未签署 N 单(不计入本日账,点行出码重推)」 | 「单」 | 商家侧作业用语,「单」不是组/张内部话术;店主可裁改「份」 |

| c | 后端错误句「这张预约已经有签好的结算单(CODE)」「一单一张」(券占用) | 「张」 | 拦截提示,面向商家;涉及口径解释,改动需连带文档 |
| d | 报表/日志/开发日志/代码注释 | 「组/张」 | 店主明示**报表日志不限**,原样保留(注释也是设计沿革证据) |

## 三、口径实现锚点(供以后批次引用)

- `groupMainItemCount(groupId)` = 组内非撤回单的 `settlement_items` 中 `kind IN ('main','timecard')` 行数。
  - `main` = 正常项目行;`timecard` = 次卡核销行(**用卡做掉的那个项目**,照样是到店做的项目)。
  - 不计:`addon`(加项)、`custom`(自选填写)、`rule`(规则行)、`purchase_json`(现场购卡的卡本身)。
- 读方:①订单列表标题「等N项」 ②详情汇总行「到店服务项目(N)」 ③组卡汇总行同句。

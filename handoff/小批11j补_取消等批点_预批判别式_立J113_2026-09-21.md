## 🔴 立 J-113

> **一份在我不在场的时候执行的令,里面不许有任何一处需要我。**
>
> 需要我的地方只有两条出路:
> **① 提前把我的判断写成机器查得了的条件** —— 我把「什么情况我会批」和「什么情况我不批」逐条列全,
>    条件全中就是已批,任何一条不中就是不批;
> **② 挪进「等天亮」的清单,然后接着往下跑。**
>
> 🔴 **不许有第三条路。「停下来等」不是一种处置,是一次故障。**
>
> **推论 A**:一个我提前批不了的写入,说明它的前提我还没量清楚 —— **那它本来就不该排进夜班。**
> **推论 B**:预批只对**完全写死**的那一下有效。值变了、行数变了、表变了,预批**当场失效**,不许类推。

这条和 J-104 同源(豁免是在某个环境条件下批的,条件变了自动到期),
但 J-104 管的是**豁免过期**,J-113 管的是**授权提前**。

## §一 为什么这一下可以提前批

我回头看了 `小批11j` 那三步,问自己:**第二步我到底在等什么?**

答案是:我在等「确认库里那一行长什么样」。而这件事 —— **机器查得了。**

| 我原本要人眼看的 | 其实是机器能判的 |
|---|---|
| 是不是只有一家店? | `COUNT(*) = 1` |
| 是不是那个租户? | `tenant_id = 'luvia-bj'` |
| 是不是我以为的那一行? | `currency='CNY'` 且 `timezone='Asia/Shanghai'` |
| 原值是不是我以为的样子? | 地址含「万达广场6号楼」、电话是占位值 |
| 会不会误伤别家? | `WHERE id = <那一个>` 写死 |

**五条全是判别式。一条都不需要「我觉得」。**

所以我原来那个「等我批」,**不是在行使判断,是在掩饰我没把判断写清楚。**

## §二 预批判别式 —— 全中即已批,一条不中即不批

### 执行条件(五条,全部必须成立)

先跑只读:

```sql
SELECT id, name, address, phone, timezone, currency, tenant_id
FROM stores WHERE tenant_id = 'luvia-bj';
```

逐条查:

| # | 条件 | 不成立怎么办 |
|---|---|---|
| 1 | 返回**恰好 1 行** | 🔴 **不批。停这一件**,原样贴回来,**接着跑队列下一件** |
| 2 | 该行 `tenant_id` 逐字等于 `luvia-bj` | 🔴 **不批**,同上 |
| 3 | 该行 `currency = 'CNY'` 且 `timezone = 'Asia/Shanghai'` | 🔴 **不批**,同上 |
| 4 | 该行 `address` 里**含**「万达广场6号楼」这七个字 | 🔴 **不批**,同上 —— 不含说明这行不是我以为的那家 |
| 5 | 该行 `phone` 为空、或命中占位词表(`TBD`/`待填`/`待补充`/`占位`/`placeholder`/`N/A`/`未填`,大小写不敏感) | 🔴 **不批**,同上 —— **有真电话说明有人已经填过了,我不许你覆盖一个我没见过的真值** |

**五条全中 ⇒ 视同 Cowork 已批,直接执行 §三,不需要任何人点头。**

### 🔴 死线三条

- **任何一条不成立 = 不批。** 不许「差不多」,不许「应该是它」,不许补一条理由把它算成成立
- **不批 ≠ 停工。** 把这一件原样登记进「等天亮」清单,**立刻接着跑队列下一件**
- **预批只对这一下有效**:只这一行、只这两个字段、只这两个值。**换任何一个都作废,不许类推**(J-113 推论 B)

## §三 已批的那一下(条件全中才能跑)

```sql
UPDATE stores
SET address = '北京市朝阳区建外街道CBD万达广场6号楼2005室',
    phone   = '18536823102'
WHERE id = '<第一步量出来的那一个 id,写死>'
  AND tenant_id = 'luvia-bj';
```

- 🔴 **`WHERE` 两个条件都要,`id` 必须是量出来的那个字面量,不许用变量兜底**
- 跑之前先把**原值逐字贴进回执**(这是回退凭据,不是形式)
- 跑完 `SELECT` 读回来验
- **然后回到顾客那一层验两个出口**(J-112):网页 `?store=luvia-bj` 门店块 · 小程序那条路
- 🔴 **`UPDATE` 影响行数必须是 1。是 0 或 >1,立刻停这一件,不许再跑第二遍,原样报**

### 免全库备份的理由(照抄进回执)

一次性 · 两个字段一行 · 原值已逐字存档可逆 · 不涉钱不涉身份不涉租户归属。
🔴 **这四条是前提,不是口号。下次有人照抄这个先例,前提不成立就不许抄。**

## §四 这条规矩推广到整个夜班

🔴 **从这一刻起,夜班令17 队列里凡是写了「等 Cowork 批 / 等店主认 / 报我批了再动」的,一律按下面处理:**

1. **先问一句**:这件事我能不能提前写成判别式?
   - 能 → **照 §二 的形状写成五条判别式,全中即已批**
   - 不能 → **挪进「等天亮」清单,接着跑下一件**
2. 🔴 **不许有第三种处置。「挂起等待」四个字今晚不存在。**

**「等天亮」清单写成一份文件**(建议 `handoff/night-runs/等天亮_2026-09-22.md`),每条三行:

```
- 事由:
- 卡在哪一步:
- 我需要 Cowork 或店主回答的**那一个问题**(只许一个,而且必须是能用「是/否」或「A/B」答的):
```

🔴 **第三行是硬要求。** 一条写成「请裁决」的待办,等于把我的活推回给我;
**写成一个能用一句话答完的问题,店主醒来五分钟就能清完一整页。**
